# 「月巴食堂」百巴箱餐饮经营小游戏 · 计划书

> 状态：**M1 / M2 / M3 / M4 已完成（百巴箱仍隐藏），M5 待做**
> 目标：在「放置月巴」的百巴箱新增一款开罗式餐饮经营小游戏「月巴食堂」。巴拉巴巴巴为了让番茄过上更好的生活，盘下一间小餐馆，招募图鉴月巴当服务员，一边扩店一边把番茄料理卖下去。

## 三、叙事与主题

### 3.1 一句话故事

> 番茄一直住在后厨旁边的小纸箱里。巴拉巴巴巴看在眼里，盘下了街角一间只有两张桌子的小店，门口挂上木牌：「月巴食堂」。它不会做饭，但它会请月巴来帮忙——于是，一间用番茄料理招待月巴、又把赚来的番茄一点点换成「更好的生活」的小店，开门了。

### 3.2 元素映射

| 经营概念     | 本作表现                                      |
| -------- | ----------------------------------------- |
| 店长       | 巴拉巴巴巴（固定角色，不参与招募，站在收银台）                   |
| 被照顾的对象   | 番茄（住在阁楼；生活等级随累计营业额提升）                     |
| 服务员 / 厨师 | 图鉴月巴（外链立绘，单色像素化）                          |
| 客人       | 图鉴月巴（外链立绘）；稀有度影响消费、耐心与小费                  |
| 菜品       | 8 道番茄料理（浓汤、饭、意面、冰沙、挞、火锅、茶泡饭、整颗番茄）         |
| 营业额      | 🍅，记在食堂自己的账本上                             |
| 口碑       | 街坊口碑 0–100，决定客流与稀有客人出现率                   |
| 扩店       | 2 桌 → 6 桌；灶位、员工位、菜单位同步扩张                  |
| 星级       | 口碑里程碑，解锁扩店上限、菜品与主题                        |
| 连击       | 「上菜连击」：短时间连续完成上菜，小费倍率上升                   |
| 番茄的生活    | 纸箱 → 阁楼小窝 → 有窗的房间 → 带阳台的家 → 屋顶花园（场景与永久加成） |

### 3.3 文案基调

- 温和、克制、带一点冷幽默；店长巴拉巴巴巴的台词短、平、偶尔扎心（沿用「很不高兴为您服务」的口癖）。

- 客人不卖萌过度，满意时给一个像素爱心，不满时只是安静离席。

- 失败不责备玩家：「今天先到这里吧，番茄已经睡了。」

- 所有文案可四语言化，**不把文字烘进背景图**。

- 文案部分单独给一个文档，方便制作者在翻译所有文本前调整。

示例：

- 开店：「木牌挂好了。今天只有两张桌子，收益应该也够番茄吃几天好的。」

- 上菜连击 10：「厨房开始跟上节奏了。」

- 客人流失：「它等了很久，还是走了。明天再加一个位置吧。」

- 升星：「街坊开始记住这家店了。」

- 番茄生活升级：「番茄搬进了有窗的房间。它站在窗边一直看着窗外的街道。」

## 四、形态与接入

### 4.1 独立页 + 百巴箱 iframe

对齐 `minesweeper.html` / `goldminer.html` / `nonogram.html` 的接入方式，不把经营逻辑塞进 `index.html`：

| 对比项  | 贪吃蛇 / 幸存者  | 月巴食堂（本方案）                   |
| ---- | ---------- | --------------------------- |
| 游戏本体 | 独立页 / 页内浮层 | 独立 `diner.html`             |
| 打开   | 百巴箱卡片      | 百巴箱卡片 → `gbFrameOpen`       |
| 关闭   | 卸载 iframe  | `fr.src='about:blank'`，回百巴箱 |
| 首页计时 | 继续运行       | 继续运行（番茄钟、生长、自动收获、自动存档）      |
| 存档   | 独立键        | 独立键 `yueba-diner-v1`        |
| 语言   | 页内字典 + 主存档 | 页内四语言 + `?lang=`；主存档只读设置    |

「不脱离原本游戏、其他功能照常」的落点：

- iframe 盖在首页之上，主游戏的番茄钟、月巴生长、自动收获、5 秒自动存档全部继续；

- 页面只负责自己的场景、模拟、音效与存档；关闭即销毁；

- 首页只加 `gb-lock`（`overflow:hidden`），不碰任何主计时器与主存档逻辑；

- 营业中阻止首页「自动刷新」打断，用 `dnBusy()` 接入现有守卫。

### 4.2 入口与隐藏策略

| 入口    | 出现位置               | 行为                       | 实装前                    |
| ----- | ------------------ | ------------------------ | ---------------------- |
| 百巴箱卡片 | 首页 dock「百巴箱」→ 卡片网格 | `gbFrameOpen` 打开，关闭回百巴箱  | **不显示**（`hidden:true`） |
| 直接打开  | 双击 `diner.html`    | 完整游玩，使用默认语言 / 设置（样机名册兜底） | 开发期可用                  |

2. **M1–M4 不改** `DEX_GAME`，避免图鉴里出现打不开的入口。
3. **M5 验收通过后**：只删除本卡片的 `hidden:true`；不触碰 `helix`、`tamago` 的隐藏标记。
4. 开发期直接双击 `diner.html`，或用 `?selftest=1` 自检，不依赖百巴箱入口。

### 4.4 名册桥与数据隔离

`diner.html` 不直接读主存档，全部数据由首页下发：

```
diner.html → parent: {type:'yueba-diner-ready'}
parent → diner.html: {
  type:'yueba-diner-roster',
  list:[{id,name,names:{en,ja,ko},color,shape,r,art,svg}],   // 已解锁 + 有外链；不足 4 位时补 svg
  tomato: 当前旅行番茄（只读展示，不参与食堂账本）
  muted, lowPower, lang
}
```

- 复用现有 `yueba-tamago-ready` 分支的过滤口径：`fgAllTypes()` → `colCount(t.id)>0` → `artURL(t)`；

- 首页新增 `names:I18N_BANNY[t.id]?.n || null`（附加字段，月巴蛋会忽略）；

- 不足 4 位有外链月巴时，追加 `svg` 兜底客人，保证首日可玩；页面标「临时帮工」；

- 子页就绪后发 `{type:'gbTheme', gbTheme:'diner'}` 同步外框纸色；

- **v1 绝不写** **`idle-yueba-save-v2`**；不改主金币、主番茄、主成就、主图鉴。

### 4.5 自动刷新保护

```js
function dnBusy(){
  if(typeof gbFrameId==='undefined'||gbFrameId!=='diner') return false;
  var fr=document.getElementById('gbGameFrame');
  var w=fr&&fr.contentWindow;
  if(!w) return true;
  if(typeof w.__dnState!=='function') return true;
  var st=w.__dnState();
  return st==='run';   // menu / prep / settle / ach 允许刷新
}
```

并在 L18812–L18815 的守卫链中加入 `if(dnBusy()) return;`。

### 4.6 四语言

- 页内字典 `zh / en / ja / ko`，键名统一 `dn_` 前缀，避免与主页面冲突；

- `?lang=` 读取，`normLang()` 同月巴蛋；

- 月巴名优先 `names[lang]`，缺失回落 `name`；

- 菜名、员工属性、结算小报、目标、成就全部走字典；

- 店招文字用 DOM 覆盖层渲染，背景图不烘字。

## 五、玩法设计

### 5.1 核心循环

```
百巴箱点「月巴食堂」
  → 标题页（继续 / 新的一天 / 店面 / 招募 / 菜单 / 名册 / 成就 / 主题 / 音效）
  → 准备页：选 3–6 道菜、排 1–4 名服务员、扩店 / 装修 / 培训
  → 开门营业 90 秒：
      客人进门 → 等位 → 入座 → 看菜单 → 点单
      → 厨房按灶位排队制作 → 出餐口
      → 服务员取餐 → 送到桌 → 用餐 → 结账 → 离店
      期间：点击服务员「打气」加速；连续上菜形成连击
  → 打烊结算（小报）：营业额 / 成本 / 工资 / 净利 / 客数 / 满意度 / 最高连击 / 今日目标
  → 口碑、星级、番茄生活等级推进
  → 进入下一天
```

没有 Game Over。经营差只是当天赚得少，第二天仍可调整。

### 5.2 一日节奏（90 秒）

| 时段   | 时间        | 客流              | 目的           |
| ---- | --------- | --------------- | ------------ |
| 开门   | 0–15s     | 每 6s 来 1 位      | 让玩家看到第一桌     |
| 午市高峰 | 15–55s    | 每 5.5s 来 1 位    | 压力段，考验灶位与服务员 |
| 平峰   | 55–78s    | 每 7s 来 1 位      | 缓冲，收尾连击      |
| 清场   | 78–90s    | 停止进客            | 让在店客人吃完、结账   |
| 打烊   | 90s       | 强制结算；未上菜的按流失计   | 小报           |

- 模拟固定 30Hz；时间用 `performance.now()` 累计，不用 `setTimeout` 链；

- 页面 `visibilitychange:hidden` 时暂停营业时钟与模拟，回来继续（与主游戏一致）；

- 不提供 2 倍速，避免数值与动画失真；节奏靠客流曲线控制。

### 5.3 客人流程

| 状态           | 行为           | 时长 / 规则         |
| ------------ | ------------ | --------------- |
| `enter`      | 从门口走到等位区     | 1.2s            |
| `waitSeat`   | 有空位则入座；无空位排队 | 队列最多 3 人；超时按耐心扣 |
| `walkToSeat` | 走到座位         | 0.8–1.6s，按排数    |
| `browse`     | 看菜单          | 1.0s            |
| `order`      | 选一道在售菜；偏好菜优先 | 1.0s            |
| `waitFood`   | 等待出餐与上菜      | 耐心 14–24s（见下表）  |
| `eat`        | 用餐           | 3–7s（按菜品）       |
| `pay`        | 结账、给小费       | 1.0s            |
| `leave`      | 走到门口消失       | 1.2s            |

**耐心**（决定放弃阈值）：

| 稀有度     | 基础耐心      | 说明            |
| ------- | --------- | ------------- |
| r1 / r2 | 24s / 22s | 普通客人，容错高      |
| r3      | 20s       | 主流客人          |
| r4      | 17s       | 消费高，等不久       |
| r5 / r6 | 14s / 12s | 稀有客人，服务不好会直接走 |

耐心修正：`+2s × 装修等级`、`+5% × 番茄生活等级`、`+口碑/50 秒`（上限 +3s）。

**满意度**（0–100，结算与小费用）：

```
sat = 100
    - max(0, waitTime - 8) * 2.5
    + waiter.affinity * 3
    + decorLv * 2
    - (点到的菜 != 偏好菜 ? 15 : 0)
clamp 0..100
```

- 满意度 ≥ 80：像素爱心 + 口碑 +0.8；

- 60–79：普通 +0.4；

- < 60：不涨口碑；

- 耐心耗尽：愤怒离席，口碑 −3，当日流失 +1，连击清零。

**消费**：

```
dishIncome = 菜品售价
tip = floor(售价 * 0.2 * sat/100 * (1 + 0.1*affinity)) + comboBonus
```

`comboBonus` 由连击倍率统一乘在 `dishIncome + tip` 上（见 5.9）。

### 5.4 服务员（月巴）

每日最多上阵 1–4 名，其余休息。服务员是图鉴月巴，有外链立绘，数值以 1–5 格像素条显示。

| 属性        | 作用                       | 范围                           |
| --------- | ------------------------ | ---------------------------- |
| 速度 `spd`  | 移动速度、取餐 / 送餐耗时           | 1–5；基础 34 px/s，每点 +6         |
| 周到 `aff`  | 满意度加成、小费倍率               | 1–5；每点 +3 sat、+10% 小费        |
| 体力 `vit`  | 连续工作上限；低于 20% 时回柜台休息     | 1–5；体力 20–40，每次送餐 −3，休息 +1/s |
| 等级 `lv`   | 解锁数值上限、工资                | 1–5                          |
| 经验 `exp`  | 每成功上菜 +1；升级需求 8/20/40/70 | —                            |
| 工资 `wage` | 每日固定成本                   | `6 + 3*lv` 🍅                |

**招募规则**：

- 每个营业日按 `day + seed` 固定生成 3 位候选人（同日刷新不换人）；

- 候选人 = 已解锁 + 有外链月巴中随机；数值按稀有度给保底（r4 至少 2 项 ≥3）；

- 招募费 = `20 + 10*稀有度` 🍅；已招募过的同一月巴不能再招（名册唯一）；

- 员工上限随店等级 1/2/2/3/4。

**培训**：花 🍅 提升一项数值 1 点，费用 `30 × 当前值`；上限受等级限制（lv1 上限 3，lv3 上限 4，lv5 上限 5）。

**体力与休息**：体力 < 20% 时该服务员自动回柜台，恢复到 50% 再接单；玩家可点击它提前返岗（不扣体力，但不恢复）。这是「多员工轮转」的唯一压力来源，不做排班表。

### 5.7 经济与番茄的生活

**食堂账本**（独立于旅行番茄）：

```
日营业额 = Σ(售价 + 小费) × 连击倍率
日成本   = Σ菜品成本 + Σ员工工资
日净利   = 日营业额 - 日成本
```

- 营业额只用于本作：扩店、招募、培训、研发、装修；

- **v1 不转入主存档旅行番茄**；结算页明确标注「记在食堂账本，不占用旅行番茄」；

- 后续如需联动，走 `yueba-diner-tomato` 消息，单日上限 50，且需用户确认（不在首版）。

**番茄的生活等级**（累计营业额，只算毛收入）：

| 等级        | 累计营业额 | 场景变化      | 永久加成                |
| --------- | ----- | --------- | ------------------- |
| Lv1 纸箱    | 0     | 后厨旁一只纸箱   | —                   |
| Lv2 阁楼小窝  | 600   | 阁楼出现毯子与台灯 | 客人耐心 +5%            |
| Lv3 有窗的房间 | 2500  | 开窗，街景视差可见 | 口碑上限 +5；解锁主题「薄荷纸」   |
| Lv4 带阳台的家 | 7000  | 阳台、晾衣绳、花盆 | 客单价 +5%；解锁主题「樱灰」    |
| Lv5 屋顶花园  | 15000 | 屋顶花园、夜空   | 全店移动速度 +8%；解锁主题「夜班」 |

### 6.2 单色像素规范

- 逻辑分辨率 **480×270**，整数倍缩放，`image-rendering:pixelated`；画布外留纸色边；

- 所有 UI 以 **8px 网格**对齐；边框 1px / 2px；硬阴影 `4px 4px 0 var(--ink)`；

- 不用圆角、不用渐变；需要明暗时用 2×2 / 4×4 Bayer 网点；

- 主色只有「纸 / 墨 / 一个点缀色」；点缀色只用于 🍅、选中态、警告；

- 图标统一为 1-bit SVG（🍅、灶、椅、心、星、喇叭），**页内不使用彩色 emoji 作为主要图标**；

- 中文用系统无衬线字体（保证清晰），数字用等宽字体；像素感由描边、网格、硬阴影承担，不依赖像素字体文件；

- 任何页面切换、按钮按下、弹窗出现都**不得闪白**；过渡用 80–120ms 网点擦除或硬切。

### 6.4 2D-HD 场景

不是「一张固定大图」，而是**可换色的程序化像素场景**：

| 层  | 内容             | 视差    | 说明            |
| -- | -------------- | ----- | ------------- |
| L0 | 窗外街景 / 天空 / 树影 | 0.3×  | 番茄生活 Lv3 后出现窗 |
| L1 | 后墙、窗框、吊灯、挂钩    | 0.6×  | 主题决定墙纸网点      |
| L2 | 地板、桌椅、客人、服务员   | 1.0×  | 可点击对象都在此层     |
| L3 | 前台、出餐口、吊灯前景、蒸汽 | 1.25× | 遮挡关系制造纵深      |
| L4 | 光柱、尘埃、暖光斑      | 屏幕    | 低功耗关闭         |

- 纵深：后排桌椅缩放 0.9、前排 1.08；后排对比度略低、前景描边更实；

- 光照：窗光 / 吊灯用网点渐变（Bayer），不透明度低；蒸汽用 3–5 个像素团缓慢上升；

- 景深：不跑实时模糊；用「背景低对比 + 前景高对比 + 光柱」模拟 HD-2D 层次，保证低端机；

- 场景在主题切换时重绘到离屏 canvas，营业中只复制静态层 + 绘制动态角色，不逐帧重画背景；

- 所有场景文字（店招、价签）用 DOM 覆盖，确保四语言可换。

### 6.5 月巴立绘处理（像素化）

客人 / 员工全部使用图鉴外链立绘，处理为像素风：

1. 首页下发 `art`（外链）与 `svg`（兜底）；
2. 预加载；加载完成前显示 1-bit 剪影占位，不空白；
3. **优先 Canvas 处理**：`crossOrigin='anonymous'` 加载成功 → 缩到 32×32（员工）/ 40×40（客人）→ 按当前主题量化到「纸 / 墨 / 点缀」→ 4×4 Bayer 抖动 → 加 1px 墨线外描边 → 缓存 dataURL；
4. **跨域失败回退**：不读像素，改用 CSS `filter: grayscale(1) contrast(1.25)` + 网点遮罩 + 1px 描边，仍保持单色观感；
5. 缓存键 `id + theme + size`，上限 120 条，LRU 清理；主题切换只重算可见的 10–15 张；
6. 动效：呼吸 1px 上下浮动、入座挤压 2 帧；不做旋转、不做高帧序列；
7. 加载失败：用 `svg` 剪影 + 首字，避免破图；
8. GIF 立绘保留原动画；低功耗下暂停（`visibility` / 替换首帧）。

全部 Web Audio 合成，无音频文件，保持离线：

| 事件                 | 音色             | 备注         |
| ------------------ | -------------- | ---------- |
| 门铃                 | 两音木琴           | 客人进门，轻     |
| 入座 / 点单            | 短 square 点击    | 音量低        |
| 下锅                 | 过滤噪声 + 短促滋滋    | 不超过 300ms  |
| 出餐                 | 金属小铃           | 提示可上菜      |
| 上菜                 | 清脆 ding + 上行三音 | 连击时音高递增    |
| 结账                 | 两枚硬币           | 依售价变音高     |
| 连击 3 / 6 / 10 / 15 | 四档音阶 + 小和声     | 用户偏好的分档奖励音 |
| 升星 / 生活升级          | 短琶音            | 不刺耳、无长混响   |
| 失败 / 流失            | 低音单音           | 不责备、不刺耳    |

- 首次点击后 `AudioContext.resume()`；静音跟随首页 `muted`；

- 不使用混响、不使用尖锐高频；总音量与主游戏一致；

- 低功耗只降视觉，不静音。

## 八、存档结构

独立键 `yueba-diner-v1`，JSON，版本号 `v=1`：

```js
{
  v:1,
  day:3, seed:1730012345,
  tomato:128,        // 食堂账本余额
  total:640,         // 累计营业额（番茄生活等级）
  rep:24,            // 口碑 0-100
  star:1,
  shop:{lv:1, seats:4, tables:2, stoves:1, staffSlots:1, menuSlots:3, decor:0},
  menu:['soup','rice','ice'],
  dishes:{soup:{sales:12}, rice:{sales:8}, ice:{sales:5}},
  staff:[{id:'mb_xian', lv:1, exp:4, spd:2, aff:3, vit:2, wage:9}],
  rosterSeen:{mb_xian:{n:3, fav:'soup', first:1}},
  ach:{firstday:1, combo5:1},
  best:{income:120, sat:88, combo:8},
  daily:{key:'20261026', targets:[...], claimed:[false,false,false]},
  theme:'cream',
  tut:1
}
```

- 保存时机：打烊结算、营业中每 5s、`visibilitychange:hidden`、页面 `pagehide`；

- 读取：`try/catch` + 字段兜底；版本不符时按默认值补，不整档丢弃；

- 损坏存档：备份原串到 `yueba-diner-v1.bak` 后重置，并 toast 提示；

- 存档体积目标 < 20KB；`rosterSeen` 最多保留 120 位；

- 存档初始化时若 `day` 缺失，按第 1 天；

- 提供设置页「清空食堂存档」，需二次确认；

- **不读写主存档**；名册、语言、静音、低功耗全部由首页下发。

## 九、性能与低功耗

- 模拟固定 **30Hz**，渲染只在营业页用 `requestAnimationFrame`；菜单 / 结算页零 rAF；

- 画布 480×270，DPR 上限 2，整数缩放；静态层预渲染，动态层每帧只画 12 客人 + 4 员工 + 3 灶位 + 特效；

- 对象池：客人 / 飘字 / 粒子复用，避免每帧 new；

- 图片缓存 + 离屏 canvas；主题切换时只重算可见立绘；

- 切后台暂停模拟与渲染；回来按真实时间补 1 次结算，不补全程；

- 低功耗：关尘埃、光柱动画、视差、震屏、礼花；背景静态；GIF 立绘暂停；

- 内存目标：常驻 < 60MB；立绘缓存 < 120 条；

- 首页不受影响：iframe 内独立运行，主游戏番茄钟 / 生长 / 自动收获继续；营业中阻止首页自动刷新。

## 十三、风险与对策

| 风险                  | 影响          | 对策                             |
| ------------------- | ----------- | ------------------------------ |
| 外链图片跨域，Canvas 无法读像素 | 单色像素化失败     | 双通道：Canvas + CSS 滤镜回退；预加载与剪影占位 |
| 名册桥延迟 / 首页未回消息      | 首屏空白        | 3 次重试 + 样机名册；加载态不空白            |
| 开罗式系统过多，首版做不完       | 延期 / 半成品    | 锁定「不做清单」；M2 只做核心营业，成长放 M3      |
| 经济数值失衡              | 前期太穷或后期无挑战  | 所有数值集中到 `BAL` 常量；用脚本跑 30 天模拟调参 |
| 2D-HD 背景美术成本高       | 风格不统一 / 包体大 | 程序化像素场景 + 主题换色，不引入大图           |
| iframe 关闭时丢进度       | 玩家损失一天      | 营业中每 5s 自动存档 + `pagehide` 保存   |
| 低端机掉帧               | 体验差         | 30Hz 模拟、静态层预渲染、对象池、低功耗         |
| 主题切换重绘卡顿            | 切换瞬间掉帧      | 主题切换在准备页完成；只重算可见立绘             |
| 与既有隐藏卡冲突            | 误上线其他游戏     | 只改本卡片 `hidden`，回归时逐卡核对         |
| 风格被误认为复制开罗          | 版权 / 口碑风险   | 只借鉴经营节奏，不使用开罗素材、UI、名称、字体       |
