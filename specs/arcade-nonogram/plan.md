# 「月巴数织」百巴箱小游戏 · 计划书

> 状态：**已实现**（`nonogram.html` + 百巴箱入口；M1–M5 完成，`?selftest=1` 通过，浏览器实测通关/金币/存档隔离正常）
> 目标：在「百巴箱」新增一个数织（Nonogram / 绘图方块）小游戏，谜底是**当前所有带外链立绘的月巴**；游玩页形态对齐贪吃蛇 / 黄金矿工，独立单文件 + 百巴箱 iframe 内嵌。
> 文件名：`nonogram.html`；独立存档键：`yueba-nonogram-v1`；游戏名暂定「月巴数织」。

## 二、已核实的数据与可行性

这些结论直接决定玩法取舍，先列在最前面：

| 项 | 实测结果 |
|---|---|
| 带外链立绘的月巴 | **89 只**（`TYPES` 66 + `TYPES2` 17 + `TYPES3` 6） |
| 不同图片 | **88 张**；`mb_xiaoyue`（小月巴）与 `mb_wan`（微笑月巴）共用同一 URL |
| 图片规格 | 抽样 4 张均为 **160×160**；PNG / GIF / WebP 混合，带透明通道 |
| 透明背景 | Alpha=0 占比 55%–76%，主体可干净抠出，适合做剪影掩码 |
| 多语言名 | 89 只全部在 `I18N_BANNY` 里有 en / ja / ko 名称 |
| 作者信息 | 已有 `YB_PIC_AUTHOR`，可在图鉴详情里署名 |
| 外链 CORS | 抽样响应**没有** `Access-Control-Allow-Origin`；运行时 `canvas.getImageData()` 会被污染 |
| 唯一解比例 | 抽样 14 只：12×12 与 15×15 下各有 **12/14 多解**；20×20 抽样 4 只仍有 3 只多解 |
| 提高分辨率 | **不能**解决多解问题；亮度阈值抠内部细节会破坏浅色月巴（白月巴会被抠空） |

因此有两个关键结论：

1. **不能在运行时读图生成谜题**。必须离线预生成，把每道题的答案位图、配色、线索一起内嵌进 `nonogram.html`。
2. **不要追求唯一解**。从立绘剪影自动生成的数织天然容易多解；强行唯一化会改坏外轮廓，逐只手工修 88 张也不现实。采用「线索满足即通关，任意合法解都算」的规则，通关后展示官方立绘，谜底仍然是月巴。

## 三、形态：独立页 + 百巴箱 iframe

对齐 `goldminer.html` / `fight.html` 的接入方式，而不是把棋盘塞进 `index.html`：

| 对比项 | 贪吃蛇 | 月巴数织（本方案） |
|---|---|---|
| 游戏本体 | 独立页 / 页内浮层 | 独立 `nonogram.html` |
| 打开 | 百巴箱入口 | `#gbGameOverlay` + `#gbGameFrame` iframe |
| 关闭 | 卸载 | `fr.src='about:blank'`，回百巴箱 |
| 首页计时 | 继续运行 | 继续运行 |
| 存档 | 独立键 | 独立键 `yueba-nonogram-v1` |
| 语言 | 页内字典 + 主存档 | 页内字典 + 主存档 |

「不脱离原本游戏、其他功能照常」的落点：

- iframe 盖在首页之上，主游戏番茄钟、月巴生长、自动收获、5 秒自动存档全部继续；
- 页面只负责自己的棋盘、计时、音效；关闭即销毁；
- 首页只加 `gb-lock`（`overflow:hidden`），不碰任何计时器与存档逻辑。

## 四、玩法设计

### 4.1 核心循环

```
百巴箱点「月巴数织」
  → 目录（88 张拓片，按稀有度分组；未解只显示名字/尺寸/稀有度，不显示立绘）
  → 选一张 / 随机未解 / 今日拓片
  → 棋盘：行/列数字 → 涂黑 / 打叉 → 线索满足
      → 失误会标红该行/列，可撤销
      → 卡住可用「提示」（3 次，只推逻辑可确定的格）
  → 通关：涂黑格逐格亮起 → 官方立绘在「拓片相框」里显影
      → 名字 / 稀有度 / 作者 / 用时 / 失误 / 提示 / 星数 / 金币
      → 下一张未解 / 重玩 / 返回目录
```

### 4.2 棋盘与线索

- 二值数织：每格只有「涂黑 / 空白」两种答案；玩家可额外打叉做草稿。
- 答案位图离线生成，运行时只负责渲染与判定。
- 线索由答案位图实时计算（行从左到右、列从上到下），不单独存数字，避免数据不一致。
- 每一行/列的线索数字在满足后变灰并划线；整行完成时有一次柔光扫过。
- **自动划叉**（默认开）：某行/列的已涂黑格数与线索完全吻合时，自动把该行剩余未知格打叉；可在设置里关闭。
- 「自动划叉」只影响草稿标记，不自动涂黑，保留推理乐趣。

### 4.3 判定规则

| 项 | 规则 |
|---|---|
| 通关 | 所有行、所有列的涂黑连续段与线索完全一致 |
| 多解 | 任意合法解都算通关；不要求与官方位图逐格一致 |
| 揭晓 | 通关统一展示该月巴的**官方立绘**与官方配色版本，不展示玩家当前像素图作为最终答案 |
| 失误 | 一次操作让某行/列变成「无任何可行排布」→ 该行标红、轻微震动、失误 +1 |
| 失败 | **没有失败**；失误只影响星数，随时可撤销/清行 |
| 重置 | 可清空重来；本局已用的提示次数不返还 |

### 4.4 行/列解算器（核心逻辑）

页面内置一个轻量的单行线解算器，负责四件事：

1. **合法性**：当前行/列的已涂黑与已打叉，是否还能排出至少一种符合线索的排列；不能则该线标红。
2. **线索满足**：已涂黑段与线索一致时，线索变灰、整行扫光。
3. **提示**：只在「该线只剩唯一可行排布」或「所有可行排布都相同的格」上落子，保证提示不会与任何合法解冲突。
4. **纯逻辑标记**：离线用同一套行/列推演，从空盘反复填「唯一排布」，算出该题是否可纯逻辑通关，作为难度标签（可选展示）。

所有可行排列按「线索签名 + 棋盘尺寸」缓存，开局只算一次；每步只做兼容性比对，15×15 下开销可忽略。

### 4.5 尺寸与难度

| 稀有度 | 棋盘 | 题数（按当前池） | 定位 |
|---|---|---|---|
| r1–2 | 10×10 | 30 | 入门，3–5 分钟 |
| r3 | 12×12 | 31 | 主力，5–8 分钟 |
| r4–5 | 15×15 | 27 | 挑战，8–15 分钟 |

- 不按稀有度锁题；全部开放，玩家可自由挑喜欢的月巴。
- 同一尺寸下，用离线 `logic` 标记区分「纯逻辑可解」与「可能需要试填」，目录里用一个小标签提示，不做硬门槛。
- 15×15 是上限：再大在 360px 竖屏上格子会小于 12px，触控和线索排布都会变差。

### 4.6 操作

| 操作 | 桌面 | 手机 |
|---|---|---|
| 涂黑 / 打叉 | 工具栏切换模式；左键点格 | 点格；工具栏切换模式 |
| 反向标记 | 右键 / 长按 350ms | 长按 350ms |
| 连续涂抹 | 按住拖动 | 按住拖动（按当前模式设置，不逐格反转） |
| 撤销 | `Ctrl+Z` / 撤销按钮 | 撤销按钮 |
| 提示 | `H` / 提示按钮 | 提示按钮 |
| 移动光标 | 方向键 | — |
| 涂黑当前格 | `Space` | — |
| 打叉当前格 | `X` | — |
| 暂停 | `Esc` / 暂停按钮 | 暂停按钮 |
| 关闭 | 外层「✕ 返回百巴箱」 | 外层「✕ 返回百巴箱」 |

- 棋盘区域 `touch-action:none`，阻止 iframe 内滚动与双击缩放。
- 格子上最小触控目标由「整块棋盘可拖动涂抹」补偿；单格点击仍准确。
- 键盘只在 iframe 聚焦时生效，关闭后随文档销毁。
- 一次拖动算一次撤销记录；撤销栈保留最近 50 次操作。

### 4.7 提示与星数

**提示**（每张拓片 3 次）：

- 找一条「只剩唯一可行排布」的行/列，自动填上其中所有未知格，并给这些格加 `✦` 角标。
- 若没有唯一排布，找一条「存在所有排布都相同的格」的线，只填这些**必然格**。
- 若两者都没有，提示不消耗，弹出「当前没有可确定的格子，先试填一格」。
- 提示只使用行/列逻辑，永远不与任何合法解冲突；不做「直接给官方答案」的硬填。

**星数**：

| 星 | 条件 |
|---|---|
| ★★★ | 0 失误、0 提示、用时 ≤ 标准时间 |
| ★★ | 满足其中两项 |
| ★ | 通关即可 |

标准时间：10×10 3:00 / 12×12 6:00 / 15×15 10:00。

- 计时从第一次落子开始；暂停、切后台时停止；通关停止。
- 只记录**最佳时间**与**最佳星数**；重复通关可刷新。

### 4.8 目录 / 图鉴

- 按稀有度分组：普通 / 常见 / 稀有 / 史诗 / 传说。
- 未解卡片：显示月巴名字、稀有度、棋盘尺寸、一个「未显影拓片」纹理；**不显示立绘**，避免直接剧透。
- 已解卡片：显示立绘缩略图、最佳时间、星数、作者署名。
- 顶部统计：`已解 n/88`、总星数、累计用时。
- 筛选：全部 / 未解 / 已解 / 仅纯逻辑。
- 收藏状态：只读主存档 `collection*`，已收集的月巴加一个「已收」小圆点；不影响可玩性。
- 双生拓片：小月巴与微笑月巴共用一道题；通关后两张卡同时点亮，详情里并列显示两个名字。

### 4.9 每日拓片（默认包含）

- 用本地日期做种子，从 88 道题里固定抽 1 道；同一天所有玩家/多次进入都是同一题。
- 每日题单独记录最佳时间与星数，不覆盖普通模式记录。
- 当天首次通关额外 +50 金币（一次性）。
- 连续 7 天完成每日题 → 本地成就「七日拓」。
- 若当天题目已解，仍可重玩刷时间，但不再发金币。

## 五、谜题资产生成流水线

### 5.1 为什么离线

外链图片没有 CORS 头，跨域画到 canvas 后 `getImageData()` 会抛安全错误；88 张图也不能让玩家每次开局现场下载、现场阈值化。离线生成一次，页面只带结果，最快、最稳、最省电。

### 5.2 流水线步骤

```
index.html（TYPES/TYPES2/TYPES3 + I18N_BANNY + YB_PIC_AUTHOR）
  → ① 提取 89 只带 img 的月巴，按 URL 去重 → 88 道题
  → ② 下载立绘缓存（GIF 取有代表性的首帧/中间帧；带 UA，避免 403）
  → ③ Alpha 通道抠图：裁到非透明包围盒
  → ④ 缩放：等比 fit 到 N×N（N=10/12/15），居中留白，再裁掉全空边
  → ⑤ 二值化：Alpha ≥ 120 记为涂黑；去掉孤立单格；保留 ≥6 格的连通块
  → ⑥ 配色：每个涂黑格取原图该区域的平均色，median-cut 量化到 ≤8 色
  → ⑦ 校验：涂黑率 8%–65%；线索重算；行解算器从空盘推演；唯一解检测（只记录，不强制）
  → ⑧ 输出：JS 数据片段 + 88 张缩略 QC 接触表
  → ⑨ 人工过一眼 QC 表：空图 / 糊成一团 / 裁切错 / 混入水印的，单独调阈值或裁切后重跑
```

### 5.3 数据格式（内嵌到页面）

```js
// 88 条，按稀有度再按 id 排序
const NP = [
  {
    id:'mb_xiaoyue', alias:['mb_wan'],      // 双生拓片：同一张图，两个名字
    n:'小月巴',                              // 中文名
    nm:{en:'Little Banny',ja:'ちびバニー',ko:'꼬마버니'},
    img:'https://origin.picgo.net/...png',
    r:1, sz:10,
    bits:'0011110000...',                    // sz*sz，行优先，'1'=涂黑
    pal:['#f2d4e6','#c9a8c9','#7a5d7a'],     // ≤8 色
    col:'012010...',                         // sz*sz，base36，仅 bits=1 的格有效
    uniq:0, logic:1,                         // 唯一解 / 纯逻辑可解（只做标签）
    by:'Nyaomi'                              // 作者（可空）
  }
];
```

- 线索不存，运行时由 `bits` 计算。
- `col` 用 base36 单字符索引 `pal`，体积约为直接存 RGB 的 1/5。
- 88 道题合计约 **35–45KB**（含名字与 URL），页面总目标 ≤ 120KB。
- 双生拓片只存一条；通关时按 `alias` 同时点亮两张图鉴卡。

### 5.4 新增月巴后的维护

- 以后图鉴新增带立绘的月巴 → 重跑 `tools/nonogram/gen.py` → 用生成片段替换 `nonogram.html` 里 `/*NP_DATA_START*/ ... /*NP_DATA_END*/` 之间的内容。
- 存档按 `id` 记录，新增题目不会影响旧进度；旧题不会消失。
- 若两张图后来改成不同 URL，去重自然拆成两道题，不需要改代码。
- 生成器与 QC 表放在 `tools/nonogram/`，不进游戏包，也不被页面引用。

## 六、视觉与音效

### 6.1 视觉方向

独立页不继承首页皮肤，采用固定的**「深夜拓印馆」**主题：深墨蓝底 + 奶油纸面板 + 番茄红/藕粉/冰蓝点缀，磨砂玻璃质感，避免霓虹与通用数织 App 的白色表格感。

| 元素 | 方案 |
|---|---|
| 页面底色 | `#12141f` → `#1a1d2b` 径向渐变，叠极淡纸纹（CSS repeating gradient，不用图片） |
| 面板 | 奶油纸 `#f6efe4` / 半透明磨砂 `rgba(246,239,228,.08)`；圆角 16–20px |
| 主文字 | 奶油 `#f6efe4`；次要 `#8a8fa8` |
| 强调色 | 番茄红 `#e2564a`、藕粉 `#f0a8c0`、冰蓝 `#a9c7ea`、传说金 `#d9b45a` |
| 棋盘 | 深色半透明底 + 细网格线 `rgba(246,239,228,.18)`；涂黑格用该题的采样色，带 1px 顶部高光与内阴影，像压进纸里的色块 |
| 打叉 | 小圆点 / 短斜线 `rgba(138,143,168,.9)`，不抢涂黑格的视觉 |
| 线索 | 等宽数字，满足后变灰 + 划线；列线索贴底、行线索右对齐 |
| 完成行/列 | 一次 260ms 柔光扫过，不闪屏 |
| 通关显影 | 涂黑格先逐格脉冲，再由中心向外交叉淡入官方立绘；外面套「拓片相框」+ 番茄红印章 |
| 目录卡片 | 未解：织纹纸 + 名字 + 稀有度；已解：立绘缩略图 + 星数 + 时间 |
| 动效 | 落子 120ms 弹入、错误 220ms 左右轻抖、通关 900ms 显影；低功耗关闭粒子与扫光 |

- 外层百巴箱条保持首页原样，不随本游戏改色。

## 八、技术方案

| 模块 | 方案 |
|---|---|
| 渲染 | **DOM 棋盘**（`display:grid`），最多 225 格；线索也是 DOM。无 canvas，无 DPR 问题，文字清晰，便于无障碍 |
| 尺寸计算 | 监听 `resize`，按可用宽高算 `--cell = clamp(12px, min((min(vw,520)-2*clueW-32)/N, (vh-250)/N), 26px)`；`clueW` 按该题实际最大段数算；10/12 格通常 16–24px，15×15 允许降到 12px |
| 游戏循环 | **无常驻 rAF**；计时用 500ms `setInterval`；只有通关显影/错误抖动时临时开 rAF，结束即停 |
| 事件 | 棋盘容器用 `pointerdown/move/up` 事件委托；按下时用坐标换算格坐标，拖动连续涂抹；`pointercancel` 收尾 |
| 状态 | `np = {puzzle, size, marks:Int8Array, hintMarks:Uint8Array, t0, elapsed, mistakes, hints, undo:[], curStroke, done}` |
| 标记值 | `-1 未知 / 0 打叉 / 1 涂黑`；`Int8Array` 存 225 格，拷贝与撤销都很轻 |
| 线解算 | 预生成 `PATTERNS[size][clueKey]`；每步对 2N 条线做兼容性检查；结果缓存 |
| 提示 | 单行唯一排布 → 填未知格；否则填「所有排布共同格」；都没有则不消耗 |
| 撤销 | 每次落笔记录 `{i, from, to}` 数组；一次拖动合并为一条；上限 50 条 |
| 通关 | 所有行列线索满足 → 冻结输入 → 显影动画 → 写存档 → 发金币 → 结算面板 |
| 图片 | 只在通关和图鉴详情加载 `<img loading="lazy" decoding="async">`；`onerror` 回退为已解像素图 + 名字，不塌布局 |
| 图鉴 | 88 张卡；未解不加载图片；已解用 `IntersectionObserver` 懒加载缩略图 |
| 卸载 | 外层 `gbFrameClose()` 把 iframe 设 `about:blank`；页内 `pagehide` 里清计时器、暂停音频兜底 |
| 低功耗 | 关震动、粒子减半/关闭、扫光关闭、`backdrop-filter` 关闭、过渡时长减半 |
| i18n | 页内字典 zh/en/ja/ko；月巴名用 `NP.nm`；`?lang=` → 主存档 `lang` → 浏览器；DOM 文案统一走 `t()` |
| 移动端 | `touch-action:none`；按钮 ≥44px；底部 safe-area；横屏时棋盘吃满高度、工具栏改侧栏或底部横排 |
| 数据 | `NP` 内嵌；线索运行时算；`col` base36；页面目标 ≤120KB |
| 测试 | 数据完整性 + 线解算器纯函数用 Node 沙箱跑；页面加 `?selftest=1` 自检（不改正常流程） |

## 十、验收标准

3. **独立可用**：直接双击 `nonogram.html` 也能完整游玩（无主存档时用默认语言、默认设置、全部开放）。

## 十二、风险与对策

| 风险 | 对策 |
|---|---|
| 剪影自动生成大量多解 | 不强制唯一解；按线索判定，任意合法解都算；通关展示官方立绘；提示只用单行逻辑，永不与合法解冲突 |
| 多解导致玩家「填对了却和官方图不一样」 | 通关统一显影官方立绘；玩家像素图只作为过程，不作为最终谜底 |
| 外链无 CORS，运行时取不到像素 | 离线预生成；页面只带位图/配色数据，不读图 |
| 图片 403 / 404 / 动画 GIF 取帧不对 | 下载带 UA；GIF 取有代表性的中间帧；生成失败标 QC；页面 `onerror` 回退像素图 |
| 88 张图里有裁切错、糊成一团、混入水印 | M1 产出 QC 接触表逐张过；对问题图单独调阈值/裁切/连通块后重跑 |
| 浅色月巴抠图后几乎为空 | 只用 Alpha 通道，不用亮度阈值；涂黑率 <8% 的题单独提高分辨率或降低 Alpha 阈值 |
| 深色/大块月巴涂黑率过高 | 涂黑率 >65% 时提高阈值或裁掉外围装饰；仍过高则换 15×15 并人工复核 |
| 15×15 在 360px 屏上格太小 | `--cell` 允许降到 12px；线索宽度按实际最大段数动态算；整块拖动涂抹补偿触控；不做 18×18 以上 |
| 225 个 DOM 格性能 | 无逐帧循环；只在状态变化时更新受影响的格；线索/结果缓存；低功耗简化动效 |
| 提示把玩家带进死路 | 提示只填「当前线唯一排布」或「全排布共同格」，逻辑上必然安全；无确定格时不消耗 |
| 玩家乱填导致无解但不自知 | 每条线实时合法性检查，无解行/列立即标红；可撤销/清行；没有失败状态 |
| 金币影响主经济 | 只在首次通关发一次，按稀有度固定小额；可一键把奖励设为 0 |
| 主存档 5 秒自动存档并发 | 只读 + 单次同步解析；失败回退默认值，不重试、不写入 |
| 外链立绘断网/换地址 | `onerror` 回退已解像素图 + 名字；图鉴缩略图懒加载，失败不塌布局 |

| 未解卡剧透 | 目录只显示名字/稀有度/尺寸，不显示立绘；HUD 在通关前只显示「拓片 #n」 |
| iframe 关闭后仍在跑 | 依赖 `gbFrameClose()` 的 `src='about:blank'`；页内 `pagehide` 清计时器、暂停音频兜底 |
