# 「月巴节拍」Banny Beat · 计划书

> 状态：**待评审，未动工**（本文件只做方案，不写代码；实装到百巴箱也放在验收之后）
> 目标：为「百巴箱」新增一款**先听后打**的节奏小游戏。第一遍只播放（试听），第二遍由玩家用**手指 / 鼠标 / 键盘**跟着刚才的音乐，在月巴身上按拍；按准确度评级。关卡由「单键正拍」渐进到「四轨切分 + 双押 + 十六分」。
> 文件名：`rhythm.html`；独立存档键：`yueba-rhythm-v1`；暂定名「月巴节拍」（Banny Beat / バニービート / 버니 비트）。
> UI：沿用贪吃蛇 / 番茄幸存者的**全息终端版式**（等宽字、细描边、四角光标、切角按钮、扫描线），但整体换成**浅色**（奶油纸 + 薄荷 + 番茄红），配色全部走 CSS 变量。

## 一、结论先行

| 项 | 决定 |
|---|---|
| 游戏形态 | 单文件 `rhythm.html`，零依赖、可离线双击打开 |
| 核心玩法 | 每关两遍：**试听（自动演奏）→ 演奏（玩家按拍）**，同一份谱面、同一个音频起点 |
| 音频 | **WebAudio 程序化合成**，不引入任何音频文件；谱面即旋律 |
| 判定 | 以 **AudioContext 时钟**为准，Perfect ±50ms / Great ±100ms / Good ±150ms；超出即 Miss |
| 计分 | 只按准确度：`(Perfect×1 + Great×0.75 + Good×0.4) / 总音数`；等级 S/A/B/C/D |
| 关卡 | 6 关，1→4 轨；正拍 → 八分 → 切分 → 双押 → 十六分；准确度 ≥70%（B）解锁下一关 |
| 输入 | Pointer Events 统一手指/鼠标；键盘 `D F J K` / `1 2 3 4`；支持多指双押 |
| 延迟 | 首次进入自动校准（跟节拍器点 8 下），另留手动偏移滑块；偏移量单独存档 |
| 渲染 | Canvas 2D 画轨道与音符；HUD / 打击区用 DOM；DPR ≤ 2 |
| 百巴箱接入 | `GB_GAMES` 追加卡片，带 `hidden:true`；验收后删标记即上线 |
| 外部框色 | 复用现成浅色主题 `t-diner`（`#F5F0E6`），**不新增 CSS**，避免打开时闪深色 |
| 经济 | 首版**不发金币/番茄、不写主存档**（与螺旋跳、俄罗斯巴块一致） |
| 主存档 | **只读**（`lang` / `muted` / `lowPower`），绝不写入 |
| 语言 | 页内 zh / en / ja / ko 字典；`?lang=` → 主存档 → 浏览器 |
| 性能 | 无 `backdrop-filter`；低功耗关粒子/扫描线/阴影；后台自动暂停 |

## 三、玩法设计

### 3.1 一关的完整循环

```
关卡卡片（难度 / 最佳准确度 / 等级 / 锁）
  → 试听：4 拍预备 → 音乐播放，音符照常下落并自动发光发声（玩家输入无效）
  → 间隔 1.5s：屏幕提示「轮到你了」
  → 演奏：4 拍预备 → 同一段音乐，玩家在音符抵达判定线时按对应月巴
  → 结算：准确度 / 等级 / 最大连击 / 各判定数量 / 是否解锁下一关
  → 重试 / 下一关 / 回选关
```

要点：试听与演奏**共用同一份谱面与同一个音频锚点算法**，保证「听到的」与「要打的」完全一致；试听阶段会显示同一条下落轨道（幽灵态），让玩家同时建立视觉记忆。

### 3.2 关卡曲线（难度唯二来源：轨数 + 节奏密度）

| 关 | 名称 | BPM | 轨数 | 小节 | 节奏型 | 约音数 | 时长/遍 |
|---|---|---|---|---|---|---|---|
| 1 | 一拍一下 | 84 | 1 | 8 | 每拍正拍，四分音符 | 32 | ~23s |
| 2 | 两只月巴 | 96 | 2 | 8 | 四分 + 每小节一组八分 | 44 | ~20s |
| 3 | 三只月巴 | 108 | 3 | 12 | 连续八分、弱拍进入 | 62 | ~27s |
| 4 | 切分月巴 | 120 | 4 | 12 | 八分切分、跨拍延音（仍是单点） | 86 | ~24s |
| 5 | 双押月巴 | 132 | 4 | 16 | 十六分短句 + 重拍双押 | 112 | ~29s |
| 6 | 月巴终章 | 144 | 4 | 16 | 十六分跑动、切分 + 双押混排 | 130 | ~27s |

设计约束：

- 轨数变化时，打击区**平分整宽**（1 轨=整条大月巴，最容易点；4 轨=四只一排），每关只用本关轨数，不做「4 轨只亮 2 轨」的假轨道。
- 第 5 关才引入双押；双押永远落在**强拍**，不放在切分位。
- 每关最后 2 小节是「收尾句」，密度略降，给玩家正反馈。
- 全部为**单点**，不做长按/滑动，保证多指与鼠标一致。

### 3.3 判定与计分

| 判定 | 窗口（默认） | 权重 | 反馈 |
|---|---|---|---|
| Perfect | ±50ms | 1.00 | 薄荷色爆环 + 清脆高音 |
| Great | ±100ms | 0.75 | 浅黄爆环 |
| Good | ±150ms | 0.40 | 灰蓝爆环 |
| Miss | 迟到 >150ms 或未击中 | 0 | 轨道抖动 + 闷音 |
| 空拍 | 该轨 ±150ms 内无音符 | 不扣准确度，仅断连击 | 轻微「咔」声 |

- 准确度 `acc = Σ权重 / 总音数 × 100%`。
- 等级：S ≥ 95%，A ≥ 85%，B ≥ 70%，C ≥ 50%，D < 50%。
- 解锁：`acc ≥ 70%` 时解锁下一关；未达标可无限重试（不消耗任何资源）。
- 连击只做展示与结算「最大连击」，不参与准确度，避免双重惩罚。
- 打击本身有音高（4 轨分别为 C5 / E5 / G5 / B5），打准=把旋律补全，打歪=走音，反馈即音乐。

### 3.4 谱面数据结构（可读、可校验）

每轨一条 16 分网格字符串，`x` 为击打，`.` 为空，多轨同一列 `x` 即双押：

```js
var CHARTS = [
  { id:'l1', bpm:84, bars:8, lanes:1, grade:'C',
    tracks:[ 'x...x...x...x...' ] },
  { id:'l2', bpm:96, bars:8, lanes:2,
    tracks:[ 'x...x...x...x...',
             '....x.......x..x' ] }
];
```

- 每小节 16 步，字符串按小节顺序拼接；启动时展开成 `[{time, lane}]`。
- 加载时校验：同轨同列不得重复、每小节至少 1 个音、`tracks.length === lanes`；不通过则控制台报错并禁用该关（仅开发期可见）。
- 试听/演奏/音效/画面全部由这张表驱动，改谱面不用改逻辑。

## 四、音频与时钟（这是本项目最关键的工程点）

### 4.1 声音全部程序化合成

| 层 | 合成方式 | 用途 |
|---|---|---|
| 打击音（4 音高） | 三角波 + 短衰减包络，带一点八度泛音 | 谱面音符本体；试听自动播放，演奏由玩家触发 |
| 低音 | 正弦波，根音每小节一次 | 稳定节拍感 |
| 底鼓 / 踩镲 | 正弦扫频 / 白噪声短包络 | 强拍与八分律动 |
| 预备拍 | 木鱼式短音，4 下，第 4 下高八度 | 试听与演奏开始前 |

- 无任何外链音频，双击即可听；体积和加载时间都可控。
- 采样率自适应，主输出挂一个 `masterGain`（0.6），静音时直接归零。
- iOS/旧 WebView：首次 `pointerdown` 时创建/恢复 `AudioContext`，并播一个 0 长度的静音 buffer 解锁。

### 4.2 时钟与「零漂移」原则

- **唯一时间源是 `audioCtx.currentTime`**，视觉与判定都不直接用 `performance.now()` 推音符位置。
- 每帧记录一次锚点：`audioNow ↔ perfNow`；输入事件到达时用最近锚点把 `event.timeStamp` 换算成音频时间，再减去校准偏移。
- 音符位置：`y = hitY - (note.time - audioNow) * pxPerSec`，`pxPerSec` 由 BPM 与可视高度推算（保证判定线以上约 2 拍可见）。
- 音乐调度：50ms 定时器 + 200ms 前瞻，把该窗口内的音符/伴奏排进 WebAudio 精确时间点；不用 `setTimeout` 直接触发发声。
- 暂停：`ctx.suspend()` + 记录暂停起点，恢复时把 `songStart` 与所有音符时间整体后移暂停时长；同时停掉已排进未来的节点。

### 4.3 延迟校准

- 首次进入（或玩家点「校准」）弹一个约 24 秒的循环节拍器，提示「跟着点 8 下」；取 8 次偏差的**中位数**存 `offset`（−150…+150ms）。
- 设置面板保留手动滑块（实时试听节拍器验证）。
- 默认 `offset=0`；校准结果单独存 `yueba-rhythm-v1`，不写主存档。

## 十一、风险与对策

| 风险 | 对策 |
|---|---|
| 音画不同步 | 只认 AudioContext 时钟；所有发声走预调度；`?debug=1` 显示偏差 |
| 手机触摸延迟大 | 自动校准 + 手动偏移；设置里可开「宽松判定」（窗口统一 ×1.4，评级仍按实际判定结果计算） |
| 旧设备 WebAudio 卡顿 | 同时发声上限 8、音符预调度窗口 200ms、低功耗关粒子 |
| 多指双押被浏览器手势吃掉 | `touch-action:none`、`preventDefault`、`user-select:none`、禁用双击缩放 |
| 内嵌时名册迟迟不到 | 300ms 超时回退内置月巴脸，绝不阻塞开局 |
| 试听太长导致烦躁 | 单遍控制在 30s 内；关卡首次之外允许「跳过试听」（不影响成绩） |

## 十三、V2 改版：敲钉子版（2026-10-29 确认）

> 本节的玩法与呈现**取代**前文的「音符下落 + 底部按轨」，其余（判定窗口、评分、关卡 BPM、试听/演奏两遍、校准、存档、多语言、接入约定）全部沿用。

**已确认**：4 洞横排；保留键盘（D F J K / 1–4）。

### 13.1 玩法
- 台面固定 4 个洞，`lane` 即洞位；每关只启用前 N 个洞：L1=1、L2=2、L3=3、L4–L6=4。
- 月巴时间轴：`t-0.45s` 探头（快速上升）→ `t` 到顶 → `t+0.15s` 缩回。
- 玩家戳月巴；戳中判定规则不变（Perfect ±50 / Great ±100 / Good ±150）。
- 戳空（窗口内该洞无音符）→ 扑空、连击清零、洞口空响。
- 双押 = 两个洞同时冒头；桌面用两个键，手机两指。
- 键盘 `KEYSETS` 继续按洞位映射；空格在单洞关卡仍可用。

### 13.2 表现
- 台面：浅色软垫 + 4 个椭圆洞口（内阴影），洞下标注按键。
- 冒出：`scaleY 0.2 → 1.12 → 1`，轻微左右摇摆。
- 命中：压成 `1.25×0.55`，弹簧阻尼约 250ms 回弹 + 奶油色软冲击环。
- 漏了：垂耳变灰缩回，洞口冒小气团；扑空：洞口弹一下。
- 连击 ≥10：月巴弹更高、压更扁（不加分）。
- 低功耗 / reduced-motion：只保留缩放，不抖动。

### 13.3 音频
- 新增 `boing`（音高上冲 + 18Hz 微颤 + 8ms 低通噪声「啵」）、`squish`、`whiff`。
- 命中音高沿用每洞 `PITCH`，保持可听旋律；双押轻 detune。
- 背景保留轻 kick/hat，bass 改软 boop 并降音量。

### 13.4 代码改动
- CSS：移除 `#pads`，台面占满 `#playArea`。
- `draw()` 重写为台面 / 洞口 / 月巴 pop+squash；删除轨道线、节拍线、判定线、下落音符。
- 新增 `layoutHoles()`、`strike(lane)`、音符可视化状态（spawn / hit / squash）。
- `judgeTap` → 按洞位判定（逻辑复用）；`loop()` 试听段改为自动敲击动画。
- 删除 `buildPads` / `padFlash`，保留 `KEYSETS`。
- 存档、结算、校准、菜单、多语言不改。
