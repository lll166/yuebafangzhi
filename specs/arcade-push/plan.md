## 0. 一句话

十五只月巴挤在一口圆锅里互相顶，谁被顶出圈外谁出局；每局随机分一只月巴给你，活到最后才算赢。

## 1. 设计目标

| 目标 | 判断标准 |
|---|---|
| 3 秒上手 | 只有「往哪走」一个操作，不需要教学 |
| 30 秒一局 | 缩圈逼出胜负，不拖沓，适合碎片时间 |
| 又憨又弹 | 推搡时整只月巴被压扁/拉长 + 接触面凹进去，是核心观感记忆点 |
| 轻 | 单文件零依赖、15 只同屏稳定 60fps、低端机可跑 |
| 可换皮 | 单色像素 + 4 套浅色配色，纯令牌切换 |
| 不抢主线 | 纯休闲，接百巴箱，不污染放置抽卡节奏 |

## 2. 设计稿（本次已交付）

[push-mockup.html](../../push-mockup.html) 是**可玩的设计稿**，用于先验证「像不像、手感对不对」，不是最终版本。已实测通过：

- 浅色单色像素 UI（4 套配色可切换：墨蓝 / 苔绿 / 砖红 / 石灰）
- 伪 3D 圆锅（透视椭圆 + 厚度 + 投影 + 虚线收缩边界）
- 15 只随机月巴（真实外链立绘，128px 像素化上采样）
- **世界观文案**：游戏名统一为「月巴推推圈」；所有月巴都是软糖做的，推挤 / 抓拽 / 出拳都不会受伤，被挤出圈外只是出局
- 月巴是**纸片剪影**：每套配色预合成墨线描边 + 纸片厚度，浅色立绘/白月巴也不会糊成椭圆；加载失败时兜底也是一张有耳朵的纸片月巴
- 月巴是**一蹦一蹦**地走，不是滑行：腾空拉伸、落地压扁、走动时左右摇摆；停下就落回地面
- **朝向翻转**：按移动 / 瞄准 / 出拳的水平方向镜像整只立绘（`facing = ±1`），带小阈值防抖；凹陷仍留在实际受击侧
- 抓拽：靠近后点/按住右下「抓」（或 K）抓住最近对手，拖着走；轻点会锁住抓握，再点/松手放开。抓握条约 1~1.6 秒就会被挣脱；贴身冲撞也会自动抓
- 操作可见：靠近对手时他头顶冒出「点/按住抓」，抓按钮就绪高亮；完整操作指引常驻在游戏方框**下方**（不遮挡战场），写明「手机用右下按钮；电脑 K 抓 / J 拳」
- 玩家手动出拳（右下「拳」/ `J`），AI 自动出拳；出手和被推都有**后摇**，出手的人自己也会失稳
- **出拳特效**：出拳瞬间只留几根速度线；**玩家使用凹陷阴影色（跟随配色），其他月巴灰色**
- 体积碰撞、互相顶、互相出拳；全场所有月巴都能互相碰撞，撞上时被压扁/拉长、接触面软软凹进（Q 弹软糖感）
- **攻击性**：每局随机指定 1 只「猎手」（出局后自动换成离玩家最近的 AI），它无视距离直奔玩家、出拳优先打玩家、抓人念头更强；其他 AI 的目标距离里玩家权重 ×0.62，出拳间隔缩短到 0.70~1.20s，抓人念头 0.85/s。猎手头顶有「!」标记
- 无粒子特效（明确不做尘埃/火花），也不做画面抖动；反馈只靠形变、扑身动作与短音
- **8-bit 芯片音乐**：程序化合成（方波/三角波 + 噪声鼓），随存活数、缩圈、时间和倾斜自动提速、加琶音/军鼓/高音层，终局最刺激
- **后期地基倾斜**：18 秒后圆盘随机换低侧并来回转，锅面低侧压暗 + 方向箭头，所有人持续往低处滑，更容易被滑出圈
- **镜头跟随缩圈**：基础取景比原来大 6~7%（`AR0 = min(W,H)·0.475`），随后按 `1 + 0.92·(1/R - 1)` 放大（最大约 1.67×）；圆盘外沿允许被裁掉，虚线圆圈始终完整留在画面内
- 出圈掉落动画、玩家标记、HUD（圈内/挤出/时间）、结算弹层、再来一局

与最终版差异（M2 起补齐）：

## 3. 玩法设计

### 3.1 一局流程

```
开局 → 3·2·1 倒计时 → 全场混战（圆锅缓慢收缩） → 只剩 1 只 → 结算
                     └→ 玩家被顶出 → 立即结算（失败）
```

- 场上固定 **15 只**月巴；其中 **1 只是玩家操控的**（每局随机分配，开局展示「你 = 某某月巴 + 头像」）。
- 另外 14 只全部是 AI，行为一致：**优先把最近的目标顶出去**。

### 3.2 胜负

- **玩家被顶出圈外 → 失败**（"判负"）。
- **玩家是最后一只留在圈内的 → 胜利**。
- 玩家挤出别人 → 挤出数 +1，作为结算面板与成就依据（不改变胜负条件）。

### 3.3 操作

| 端 | 操作 |
|---|---|
| 手机 | 单指按在画面任意处，月巴朝手指方向加速；松手逐渐停下 |
| 桌面 | 按住鼠标拖动（同上逻辑）；`WASD / 方向键` 备用 |
| 抓拽 | 靠近后点/按住舞台右下「抓」（或按住 `K`）：抓住最近对手；轻点锁住，再点/松手放人；拖动走位就能拖行 |
| 出拳 | 手机点舞台右下「拳」按钮（第二根拇指），桌面按 `J / Enter`；不打断拖拽 |
| 通用 | `空格` 暂停；右上 `❚❚` 暂停 |

不做虚拟摇杆：**"追手指"比摇杆更容易表达推力方向**，也符合本项目一贯的手机优先。

### 3.4 出拳（玩家手动 · AI 自动）

- 玩家：手动出拳，冷却 `0.52s`、蓄力 `0.10s`；目标优先「抓住自己的人 / 自己抓着的人」，其次面前最近的一只；够不着就空挥（前扑 + 轻音，不白按）。
- AI：保持自动出拳循环（冷却 `0.70~1.20s` → 蓄力 `0.16s` → 命中/落空），猎手优先把拳头落在玩家身上。
- 蓄力表现：身体先往后仰 + 轻微放大；出手时向前一扑（位移冲量 + squash）。
- 命中效果：目标吃一次冲量（按质量比修正，重的打得狠）、猛压扁 + 软糖凹陷、软糯短音（三角/正弦 + 低通 + 音高上滑）。**不做震屏/画面抖动**。
- **后摇**：出手的人自己也会前扑失稳，玩家 `0.44s` / AI `0.62s` 内走不动、跳不了、出不了拳；挨揍的人后摇 `1.0s`，期间被打断蓄力，只能趴着挣扎着爬起来。
- 后摇表现：身体保持压扁、左右小幅挣扎摇摆（幅度随剩余时间衰减），起身时慢慢回正 —— 做出"努力爬起来"的吃力感。
- 出拳**特效**：几根速度线（不画残影、不画拳弧；命中靠压扁 + 软糖凹陷 + 音效）。**玩家速度线用凹陷阴影色 `P.ink`（跟随配色），其他月巴灰色 `#5c6573`**。不做雾/火花/碎片，也不抖屏。

### 3.4.1 抓拽（玩家与 AI 通用）

- **抓住**：两条路径——① 靠近后点/按住右下「抓」（或按住 `K`）主动抓最近对手，轻点锁住、再点/松手放开；② 两人接触且一方正在往对方身上用力时自动抓握。
- **找得到**：对手进入抓取距离时，头顶冒出「点/按住抓」；「抓」按钮就绪时会高亮加粗，并显示「点 / 按住」字样；完整操作指引常驻在游戏方框下方，开局卡片只保留目标说明和开始按钮。
- **拖行**：抓住的一方把对方拉到身前，可以拖着他往圈边挪；被抓的一方移动减速，但仍能往反方向挣，并会周期性抽动。
- **挣脱**：抓握力随时间、相对拉扯速度、被抓者挣扎持续流失，基础约 `1.1~1.6s` 就会松脱；出拳命中任一方、任一方后摇、距离被扯开、AI 自己快出圈时也会松手。
- **反制**：被抓时点「拳」直接打抓人者，带额外甩飞；自己抓着人出拳等于贴身甩出去（冲击 ×1.45）。
- **表现**：两人之间一条抻紧的虚线 + 两只小爪 + 抓握条（玩家相关时显示），松脱时弹开并冒出「挣脱! / 甩出去!」。

### 3.5 缩圈（核心节奏器）

- 锅半径 `R` 从 `1.0` 在 **76 秒**内收到 `0.58`（缓动 `k²`，前段慢、后段急）。行动变慢后圈也放慢，节奏才对得上。
- 收缩边界以虚线椭圆显示（不再画圈外斜纹，避免后期倾斜时出现杂乱的斜杠）。
- 圈变小 = 实际"推力"变大：边界不断把人挤向中心，混战自然收敛。
- 安全阀：若 100 秒仍未分胜负，进入终局速收（10 秒内收到 0.42），保证每局有终点。
- **镜头**：`AR = AR0 · (1 + 0.92·(1/R − 1))`，基础 `AR0 = min(W,H)·0.475`；圈越小画面越近，锅沿允许裁切，但虚线圆始终完整可见；鼠标/触摸坐标用同一 `AR` 做逆映射。

### 3.5.1 后期地基倾斜

- **触发**：`T > 18s` 开始，强度随时间从 0.40 推到 1.0；存活 ≤4 时至少 0.62，≤2 时至少 0.92。
- **随机换向**：每 2.6~5.2 秒随机选一个新的“低侧”方向，平滑转过去；锅面同时做轻微旋转、剪切和纵向挤压（只变换锅面/站位，立绘仍竖直）。
- **滑动力**：所有人持续受到指向低侧的加速度（最大 `1.0·amt`）+ **不被摩擦抵消的直接滑移**（`0.28·amt` 世界单位/s）+ 少量横向漂移；满倾斜时站桩滑速约 0.66/s，即使反向全速跑也会被慢慢推回低侧；实测满倾斜 1 秒位移约 0.48（约锅半径的一半）。
- **提示**：锅面低侧压暗、高侧提亮，低侧边缘出现方向箭头；第一次触发弹出「地基倾斜!」并配低频音；音乐同步加层提速。
- **输入不飘**：鼠标/触摸坐标经过视图逆变换再换算成世界坐标，倾斜时手指指哪月巴走哪。

### 3.6 AI

```
若被抓住 → 先往反方向挣
若抓着人 → 把猎物往锅边拖；自己靠近锅边就松手（不自杀）
猎手（每局 1 只，出局后自动换最近的一只）：
  若自身距圆心 ≤ 0.90R → 无视距离直奔玩家
  出拳优先打玩家，抓人念头 1.5/s
其他 AI：
  若自身距圆心 > 0.76R → 朝圆心逃（不自杀）
  否则 → 追最近的一只；距离里玩家 ×0.62 权重；出拳间隔 0.70~1.20s；抓人念头 0.85/s
叠加小幅正弦摆动（相位随机），避免机械直线
```

- AI 速度上限低于玩家（0.375 vs 0.55），**玩家操作更强**，胜利靠技巧而不是运气。
- AI 也会主动抓人（有抓握冷却与随机念头），但抓握很容易被玩家用反方向拖动/出拳挣脱。
- 猎手头顶画一个「!」圆标，玩家能一眼看出哪只冲自己来；猎手出局后标记立刻转移到新的猎手。

### 3.7 局外

- 随机选月巴：开局随机，结算面板显示本局用的是谁。
- 记录：最佳坚持时间、单局最多挤出、累计挤出、总局数、胜场。
- 成就（见 §8.3）：如「一击双杀」「零被推出局」「用最重的月巴赢」。
- 奖励（待确认）：金币 + 番茄；每日首胜再给固定奖励。

### 3.8 8-bit 音乐

- 全部 WebAudio 程序化合成，零外链：方波低音、方波/三角波琶音、噪声军鼓/踩镲、正弦底鼓；A 小调 `Am–F–C–G`，基础 132 BPM。
- 紧张度 `i`（0~1）= 时间 + 缩圈 + 存活数 + 地基倾斜；`i` 越高：BPM 132→172、琶音从 8 分变 16 分、加五度层/军鼓/16 分踩镲、主旋律升八度、低通滤波更亮。
- 存活 ≤3 时强制 `i ≥ 0.86`，≤2 时 `i ≥ 0.96`，并加高音催命 16 分音符；暂停/静音/结算自动停止排程，开局点击手势启动 AudioContext。
- SFX（推挤/出拳/挣脱/出局）仍走原有短音，和音乐共用同一个 AudioContext，音量分层独立。

## 4. 视觉设计

### 4.1 风格定义

单色像素 = **一套颜色里做明暗**，不是灰阶：纸面色底 + 单一墨色（含 2~3 级深浅）+ 硬边像素块 + 切角卡片。

- 无渐变、无模糊、无投影模糊：一律**实心色 + 2px 硬边 + 硬阴影偏移**
- 立绘是全场唯一的彩色：**人物保留原色，界面与场景严格单色**（可选「单色化立绘」开关，压饱和 + 叠墨色）
- 像素化：立绘先降采样到 128px 再整数倍放大（`imageSmoothingEnabled=false`），外加墨线剪影描边与纸片厚度
- 形变留白：贴图画布 `312×312`（内容 128px，四周各留 92px），压扁/拉长/摇晃/描边都在留白内发生，战斗中不会被贴图边缘裁切

### 4.2 配色令牌

| 令牌 | 用途 | 墨蓝 | 苔绿 | 砖红 | 石灰 |
|---|---|---|---|---|---|
| `--paper` | 页面底 | `#f5f2e8` | `#f4f2e7` | `#f7f0e7` | `#f4f4f1` |
| `--paper2` | 卡片/锅面 | `#eae5d7` | `#e7e6d6` | `#ecdfd1` | `#e6e6e2` |
| `--ink` | 主墨（文字/边框/锅边） | `#2b3350` | `#33402e` | `#4a2b25` | `#303238` |
| `--ink2` | 次级文字 | `#5d6684` | `#67765f` | `#8a6058` | `#6b6e79` |
| `--side` | 锅体厚度 | `#c9c3b0` | `#c6c7b2` | `#d3bfae` | `#ccccc8` |
| `--line` / `--hi` | 细线 / 高光内框 | 见设计稿 | | | |

切换方式：`<html data-pal="ink|moss|brick|ash">` + CSS 变量，画布从同一份 JS 调色板取色 → **一次点击全页同步换色**。

### 4.3 伪 3D 投影

俯视圆锅按固定倾角压扁，元素按 `y` 排序：

```
屏幕 X = CX + x · AR
屏幕 Y = CY + y · AR · KY        KY = 0.60（倾角）
缩放   = 1 + y · 0.12            （越靠前越大）
AR = min(W,H) · 0.445，CY = 0.535·H
```

圆锅构成：桌下投影 → 两层错位圆盘（厚度）→ 锅面 → 三层同心刻度 → 六等分射线 → 中心十字 → 虚线收缩边界。

### 4.4 UI 组件（延续贪吃蛇 / 番茄幸存者的视觉语言）

| 组件 | 说明 |
|---|---|
| 顶栏 | 品牌「月巴推推圈 / PUSH RING · 15」 + 统计芯片（圈内 / 挤出 / 时间） + 🔊 + ❚❚ |
| 芯片 | 2px 墨边 + 切角 `clip-path` + 硬阴影，按下位移 1px |
| 舞台 | 3px 墨边 + 内外双框 + 7px 硬阴影 + 四角 L 形括号 + 细扫描线（不透明度 ≤ 5%） |
| 弹层 | 纸面 + 3px 墨边 + 内虚线框 + 大标题字 + 切角主按钮 |
| 底部 | 「你操控：某某月巴」 + 4 个配色方块 + 一行操作提示 |

### 4.5 立绘处理

- 来源：`index.html` 的 `TYPES / TYPES2 / TYPES3`，只取 `img / imgs[0]` 有外链的条目（当前 122 只，脚本自动同步）。
- 尺寸：只取正方形包围盒（现有投稿均为 160×160、透明底）；按 `artScale` 微调留白。
- 渲染：降采样 → 压扁/拉长 → 软糖凹陷 → 放大；失败/未加载时回退为纸片月巴兜底。
- 可选：`filter: saturate(.35)` 单色化开关，让画面更像"一份印刷品"。

## 5. 推挤物理与软糖形变（核心）

### 5.1 体积碰撞

每只月巴是一个圆：半径 `r`、质量 `m = (r/0.1)²`，**碰撞半径只有立绘半径的 0.62**（互相咬进去很多，不再像两个球相切留缝）。

```
重叠 → 按质量反比分离，只解开 78%（留咬合，贴得越近越像软糖）
沿法线做冲量：restitution = 1.25（软，不一碰就弹开）
持续接触 → 额外挤压力 ov · 10     （顶住时有实感，但不抽搐）
摩擦：v *= e^(-2.6·dt)
```

### 5.2 形变模型（整只压扁、拉长、软糖凹陷）

| 通道 | 含义 | 触发 | 回弹 |
|---|---|---|---|
| `sq` | 沿接触法线**压扁 / 垂直方向拉长**（squash & stretch） | 碰撞冲量 / 出拳 / 落地 / 起跳 | 软弹簧 `k=18, c=2.2`（Q 弹，压下去会回弹两次） |
| `dent` | 接触面压出**软糖凹陷**（软边圆坑 + 内阴影 + 外圈挤起的亮环 + 坑底柔光） | 重叠深度（上限 0.9）/ 被拳打中（0.88） | 弹簧 `k=48, c=4.0`，按下后软软地弹回来 |
| `jig` | 整只立绘在贴图格里**甩一下再晃回来**（果冻抖） | 碰撞 / 出拳 | 弹簧 `k=55, c=5`，位移上限 3.8px |
| `wob` | **二次果冻扭动**（和主压扁不同频率的微旋转） | 碰撞 / 出拳 / 落地 | 弹簧 `k=30, c=2.0`，角度上限 ±0.55，绘制乘 0.35 |
| `lean` | 出拳蓄力**后仰**，出手前扑 | 出拳循环 | 随蓄力进度 0→1，瞬间归零 |
| `rec` | **后摇**：趴着挣扎、慢慢爬起来（期间不能走/跳/出拳） | 出手或被推 | 出手 0.44s（玩家）/ 0.62s（AI） / 被推 1.0s，起身曲线 `(rec/recMax)^1.6` |
| `grip` | 抓握力（0~1，玩家相关时画抓握条） | 抓住别人 | 随时间/拉扯/挣扎流失，约 1~1.6 秒松脱 |

- 碰撞半径取立绘半径的 **0.62**，立绘铺满贴图格：两只月巴会明显咬在一起、接触面软软凹进，中间不再留"球体相切"的空隙。
- 位置分离只解开 78% 重叠，冲量 restitution 1.25（软），持续挤压力降到 `ov · 10`，贴着顶也不抽。

- 压扁/凹陷方向都在**屏幕空间**取角度（`atan2(ny·KY, nx)`），视觉上才是"顺着观众看到的方向变形"。
- 待机时有 ±0.014 的轻微呼吸，接触时才夸张，避免常驻抖动。
- 压扁上限 0.64，缩放系数收敛到 `(1-0.68·sq, 1+0.54·sq)`：撞得再狠也能认出角色，不会缩成椭圆；凹陷半径随压扁量收缩（`R = R0·(1-0.30·sq)`），不会溢出轮廓。
- 纸片渲染：128px 贴图按配色预合成「墨线剪影（八向）+ 纸片厚度 + 原图」，每帧只画一次；倾斜绕靠下的支点，影子是脚边一条而不是大椭圆。
- 全场所有月巴（含玩家）都参与碰撞，没有"无敌/穿透"个体；重量只影响被推开的距离。

### 5.3 软糖凹陷算法（设计稿实现）

受击侧压出一个软圆坑，不画硬折痕：

```
坑心   = 圆心 + 受击法线 · 0.52·R
坑半径 = 0.92·R
1. destination-out 软边径向压入（中心 alpha 0.30·dent，不挖穿轮廓）
2. source-atop 坑内暗面（0.40/0.22·dent）+ 外圈被挤起的软肉亮环（0.17·dent）
3. 坑底柔光（0.18·dent）→ 软糖被按下去的湿润感
4. dent 弹簧回弹：k=48, c=4.0，按下去后软软地弹回来
```

- 全部按当前像素合成：立绘透明区不受影响，锅面刻度与射线也不会被抹掉。
- 压扁用 `scale(1-sq·0.68, 1+sq·0.54)`：法线方向缩、切线方向胀，像软糖被按扁。
- 软弹簧（`k=18, c=2.2`）→ 压得快、回弹两次，Q 弹但不抽搐。

### 5.4 渲染管线（每只 / 每帧）

```
1. 312×312 离屏画布 clear（内容 128px，四周 92px 形变留白）
2. translate(蓄力后仰 + 走动摇摆 + 果冻抖动) → rotate(tilt 左右倾) → rotate(sqDir) → scale(1-sq·0.68, 1+sq·0.54) → rotate(-sqDir) → 朝向翻转 → drawImage(立绘)
3. 软糖凹陷（destination-out 软边压入 + source-atop 暗面/亮环/柔光，见 §5.3）
4. 主画布 imageSmoothingEnabled=false 放大到 2r·AR·(1+y·0.12)，再上移 hopH·0.26·尺寸（腾空）
5. 出圈时叠加：向外推 + 下坠 + 缩小 + 淡出（1.05s）
```

> 关键点：凹陷的阴影/亮环用 `source-atop`，只在立绘 alpha 内部绘制；软边压入也用低透明度，绝不抹背景或锅面刻度。

### 5.5 蹦跳与摇摆（行走表现）

月巴从不"滑行"，靠身体一蹦一蹦往前挪：

```
mv   = min(1, |v| / 0.34·玩家)     速度越快跳得越急（AI 用 0.22）
hop += dt · (2.2 + 2.0·mv)         每秒 2.2~4.2 跳
跳高  = sin(π · min(1, hop/0.84)) · (0.15 + 0.13·mv)   走得快才跳得高，小碎步只轻轻离地
hop≥0.84 → 落地：sqDir=π/2（竖着压），sqV += 0.28 + 0.34·mv，并给 wob 一个扭动
hop≥1   → 绕回 0，起跳：sqDir=0（竖着拉长），sqV += 0.10 + 0.09·mv（0.84~1 是踩在地上的那 16%）
mv<0.10 或 rec>0 → hop 指数回零（停下来就站稳；趴着时不跳）
```

- 落地压扁的时机对准「真正踩到地面」的 0.84 相位（不是绕回 0 时），压扁和触地同一帧，不"抽"。
- 腾空时整只**纵向拉长**（`sq += air·(0.05+0.06·mv)`），落地时补一次竖向压扁 + 二次扭动 → 一跳一弹。
- 绘制位置随跳高上移（最大 `0.28×像素尺寸`），影子同步**缩小 + 变淡**，玩家箭头标记也跟着抬起来。
- 走动时叠加**摇摆 + 二次扭动**：`sway` 左右摆、`tilt` 左右倾，再叠加 `wob·0.35` 的微旋转；相位逐只随机，避免全员同手同脚。
- 待机时轻微呼吸（sq 呼吸）+ 小幅度左右晃 + 上下浮动，停下来也软软的。
- 后摇期间叠加**挣扎**：同相位的高频小幅摆（`rp^1.6` 为幅度），越到后段摆得越弱，像撑起来那一下。
- 摇摆与压扁都在 312px 贴图画布内完成，不额外开画布、不加粒子。

## 6. 技术方案

### 6.1 形态

- 单文件 `push.html`，零依赖、纯 Canvas2D + CSS，双击可玩、可 iframe 内嵌。
- 逻辑与渲染同文件，约 800~1000 行；数据（立绘表）由脚本生成，不手写。

### 6.2 主循环与性能

| 项 | 方案 |
|---|---|
| 帧循环 | `requestAnimationFrame`，`dt` 夹在 `1/30 ~ 1/60` |
| 尺寸 | 舞台 1:1，`min(600px, 97vw, 100dvh - 116px)`（手机接近满屏宽）；DPR 上限 2 |
| 静态层 | 圆锅预渲染到离屏 canvas，仅在 resize / 换色 / 缩圈跨阈值时重画 |
| 动态层 | 15 张 64² 离屏 + 主画布，无粒子系统，飘字 ≤ 6 |
| 预算 | 中端手机单帧 CPU < 3ms，GPU 仅一次全屏合成 |
| 降级 | `low-power` 时关阴影、关扫描线、关待机呼吸、削圆锅刻度（无粒子可关） |

### 6.3 省电

- 读主存档 `S.lowPower`（与幸存者同口径）；`body.low-power` 全局压动画。
- 页面失焦（`document.hidden`）自动暂停，回来继续 —— 与番茄钟的既有规则区分开（本游戏不影响番茄钟）。

### 6.4 自适应

- 320px 窄屏：HUD 芯片缩到 3px 内边距、字号 -2px，标题只留中文。
- 安全区：`env(safe-area-inset-*)` 全包，横竖屏都不裁切。

## 9. 风险与取舍

| 风险 | 影响 | 对策 |
|---|---|---|
| 立绘画风/留白不统一 | 视觉参差 | `artScale` 逐只微调；统一像素尺寸；可选单色化 |
| 15 张外链图首屏加载慢 | 开局空白 | 预加载 + 进度遮罩；失败回退“有耳朵的纸片月巴”（不是墨色椭圆） |
| 推挤穿插/抖动 | 手感崩 | 固定子步长 + 位置分离 + 质量加权；必要时 2 次迭代 |
| 形变在低分辨率下发糊 | 卖点丢失 | 128px 贴图 + 剪影描边/纸片厚度（每套配色预合成一次），压扁幅度收敛到不再变椭圆 |
| 全员围殴玩家 | 体验差 | AI 目标选择加"最近"而非"总针对玩家"；玩家速度优势 |
| iframe 内 `100vh` 失效 | 布局错位 | 用 `flex:1` + `min-height:0`，不依赖 vh |
| 与主游戏争存档 | 数据丢失 | 子页只读 + 父页统一回写奖励 |
