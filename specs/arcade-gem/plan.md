# 「宝石月巴」百巴箱三消小游戏 · 计划书

> 状态：**计划中（未实装）**
> 目标：在「放置月巴」的百巴箱新增一款宝石三消（Bejeweled 类）小游戏「宝石月巴」，从**钻石月巴**接入；实装完成前，百巴箱内**不显示**该卡片。
> 文件：`bejeweled.html`；独立存档键：`yueba-bejeweled-v1`。

***

## 三、叙事与主题映射

### 3.1 一句话故事

> 钻石月巴在鉴定台前坐下，把一盒成色不一的宝石倒在浅色绒布上。它要一颗颗比对，把同品质的宝石归到一条线上。归对了，鉴定镜亮起；归得漂亮，整盘都会共鸣。

### 3.2 元素映射

| Bejeweled 概念 | 本作表现                    |
| ------------ | ----------------------- |
| 宝石           | 7 种**品质**的宝石，各有独立颜色与外形  |
| 交换           | 月巴用镊子把两颗宝石调换位置          |
| 三连           | 3 颗同品质宝石排成一线，盖上「同品」小印章  |
| 连锁           | 宝石落位后再次成线，称为「二次比对 / 连锁」 |
| 4 连          | 生成**鉴定镜**，消除整行或整列       |
| 5 连          | 生成**品质印章**，消除全盘同品质宝石    |
| 死局           | 盘面没有可交换成线的组合，月巴重新铺台     |
| 计时           | 鉴定台的沙漏                  |
| 结算           | 「鉴定报告」：分数、最高连锁、归位宝石数    |

### 3.3 文案基调

- 温和、专注、带一点鉴定所的仪式感，不吵闹、不卖萌过度。

- 反馈强调「归位 / 对上品质」，而不是「爆炸」。

- 失败不责备玩家，例如「沙漏见底了，这一盘就先请回吧」。

- 月巴台词克制，只在关键节点出现（开局、连锁 3+、鉴定镜、结算）。

示例：

- 开局：「绒布铺好了。把同品质的宝石放到一起吧。」

- 连锁：「非常完美的操作。」

- 鉴定镜：「镜子能让你看清一整行的bao'shi。」

- 结算：「鉴定完成，恭喜。」

## 四、形态与接入

### 4.1 独立页 + 百巴箱 iframe

对齐 `minesweeper.html` / `goldminer.html` / `nonogram.html` 的接入方式，而不是把棋盘塞进 `index.html`：

| 对比项  | 贪吃蛇 / 幸存者  | 宝石月巴（本方案）                       |
| ---- | ---------- | ------------------------------- |
| 游戏本体 | 独立页 / 页内浮层 | 独立 `bejeweled.html`             |
| 打开   | 百巴箱或图鉴入口   | 百巴箱卡片；M5 后增加钻石月巴图鉴入口            |
| 关闭   | 卸载 iframe  | `fr.src='about:blank'`，回百巴箱或回图鉴 |
| 首页计时 | 继续运行       | 继续运行                            |
| 存档   | 独立键        | 独立键 `yueba-bejeweled-v1`        |
| 语言   | 页内字典 + 主存档 | 页内字典 + 主存档只读                    |

「不脱离原本游戏、其他功能照常」的落点：

- iframe 盖在首页之上，主游戏番茄钟、月巴生长、自动收获、5 秒自动存档全部继续；

- 页面只负责自己的棋盘、计时、音效；关闭即销毁；

- 首页只加 `gb-lock`（`overflow:hidden`），不碰任何计时器与存档逻辑。

### 4.2 两条入口

| 入口       | 出现位置                 | 行为                                             | 实装前                    |
| -------- | -------------------- | ---------------------------------------------- | ---------------------- |
| 百巴箱卡片    | 首页底部 dock「百巴箱」→ 卡片网格 | `gbFrameOpen` 打开，关闭回百巴箱                        | **不显示**（`hidden:true`） |
| 钻石月巴图鉴入口 | 图鉴 → 钻石月巴详情 / 卡片     | `dexGemEntry()` → `gbFrameOpen(g,'dex')`，关闭回图鉴 | **不接入**（M5 再加）         |
| 直接打开     | 双击 `bejeweled.html`  | 完整游玩，使用默认语言/设置                                 | 开发期可用                  |

### 4.3 实装前隐藏策略

1. **M1 起**就把卡片配置写进 `GB_GAMES`，但带 `hidden:true`；`gbRender()` 已原生跳过，箱内看不到，也不会影响现有 7 张卡。
2. **M1–M4 不改** **`DEX_GAME`**，避免钻石月巴详情页出现一个打不开的按钮。
3. **M5 验收通过后**：删除卡片上的 `hidden:true`，同时接入 `DEX_GAME` 与 `dexGemEntry`。
4. 开发期直接双击 `bejeweled.html`，或用 `?selftest=1` 自检，不依赖百巴箱入口。

### 4.4 接入改动总览

| 位置               | 改动                                                                                                   | 阶段 |
| ---------------- | ---------------------------------------------------------------------------------------------------- | -- |
| `GB_GAMES`       | 追加 `{id:'bejeweled', codex:'mb_zuanshi', name:'宝石月巴', sub:true, html:'bejeweled.html', hidden:true}` | M1 |

## 五、玩法设计

### 5.1 核心循环

```
百巴箱点「宝石月巴」
  → 标题页（模式 / 难度 / 每日 / 最佳记录 / 成就 / 静音）
  → 开局：铺满 8×8 宝石，保证无初始三连、至少有一步可走
  → 交换相邻宝石
      → 成线：消除、计分、上方宝石下落、补充新宝石
      → 连锁：落下后再次成线，连锁倍率上升
      → 未成线：宝石弹回原位，不扣步数
  → 4 连生成鉴定镜 / 5 连生成品质印章
  → 时间耗尽或步数用完
      → 鉴定报告：分数 / 最高连锁 / 归位宝石 / 新纪录
      → 再来一局 / 换模式 / 返回
```

### 5.2 棋盘与模式

| 模式   | 棋盘  | 规则                  | 定位            |
| ---- | --- | ------------------- | ------------- |
| 限时鉴定 | 8×8 | 90 秒；第一次有效交换开始计时    | 主力模式，1–2 分钟一局 |
| 限步鉴定 | 8×8 | 25 步；未成线的交换不计步      | 喜欢慢慢想的玩家      |
| 每日鉴定 | 8×8 | 90 秒；按本地日期固定种子，同日同盘 | 每天一把，不发奖励     |

难度只改**品质种类数**，不改规则：

| 难度 | 品质种类 | 说明              |
| -- | ---- | --------------- |
| 见习 | 5 种  | 容易成线、连锁多，适合第一次玩 |
| 正式 | 6 种  | 标准体验；每日鉴定固定为正式  |
| 大师 | 7 种  | 盘面更杂，需要更主动地做连锁  |

- 全部难度开放，不设解锁门槛。

- 8×8 在 360px 宽下每格约 40–42px，可稳定点按。

- 最佳分数按「模式 × 难度」分别记录，每日单独记录。

### 5.3 七种品质

品质用**颜色 + 外形 + 内部符号**三重区分，不依赖颜色单独辨识（照顾色觉差异）。每颗宝石都有兔耳朵，有的笔直，有的wan'qu。

| 品质  | 主色        | 外形  | 内部符号                               |
| --- | --------- | --- | ---------------------------------- |
| 白玉  | `#E7E0D2` | 菱形  | 微笑（戴着眼镜）                           |
| 薄荷玉 | `#7FCFB1` | 三角形 | 微笑（戴着墨镜）                           |
| 玫瑰石 | `#E6A0AE` | 六边形 | wink表情（戴着眼镜）                       |
| 海蓝石 | `#93B4E2` | 方形  | 无表情，冷静（戴着眼镜）                       |
| 紫晶  | `#B79BD8` | 五边形 | 皱眉，看不到眼镜（戴着眼镜，眼镜反光）                |
| 蜜蜡  | `#E2B76C` | 椭圆  | 眩晕（戴着眼镜）                           |
| 墨晶  | `#5D5A63` | 圆形  | 得意的表情，眼镜有红色眼影（上方戴着黑色圆圈，圆圈上下fu'don） |

- 所有宝石带 1px 深色描边与左上高光，浅色底上仍清晰。

- 墨晶只在大师难度出现，用于增加盘面复杂度。

- 宝石图形用 Canvas 绘制，不引入图片资源。

### 5.4 消除、特殊宝石与连锁

| 规则      | 定义                                                   |
| ------- | ---------------------------------------------------- |
| 基础成线    | 横/竖 3 颗及以上同品质                                        |
| 4 连     | 生成**鉴定镜**：消除该宝石所在的整行（横向成线）或整列（纵向成线）                  |
| 5 连及以上  | 生成**品质印章**：被消除时清除全盘同品质宝石                             |
| L / T 形 | 按「参与的宝石总数」判定；达到 5 颗即生成品质印章                           |
| 特殊宝石位置  | 生成在本次交换落点（若落点不在连线中，取连线中心格）                           |
| 特殊触发    | 特殊宝石再次参与成线时立即触发；触发后再结算连锁                             |
| 连锁      | 消除并落位后再次成线，chain +1；倍率 `1 + 0.5 × (chain - 1)`，上限 ×5 |
| 双特殊     | 首版不做特殊宝石互相交换的组合效果，避免规则膨胀                             |

### 5.5 计分

| 项      | 分值                                     |
| ------ | -------------------------------------- |
| 基础宝石   | 每颗 20 分                                |
| 3 连    | 60 分                                   |
| 4 连    | 80 分 + 40 长度奖励                         |
| 5 连及以上 | 100 分 + 100 长度奖励                       |
| 鉴定镜触发  | 被清除的每颗 20 分 + 100 触发分                  |
| 品质印章触发 | 被清除的每颗 20 分 + 150 触发分                  |
| 连锁倍率   | 上述得分 × `min(5, 1 + 0.5 × (chain - 1))` |

- 分数向上取整，HUD 用滚动数字反馈。

- 单次消除超过 8 颗时，屏幕轻震 2px，并弹出「大颗鉴定」提示（低功耗关闭）。

### 5.6 操作

| 操作   | 桌面              | 手机                 |
| ---- | --------------- | ------------------ |
| 交换   | 按住宝石拖向相邻格，松手    | 同左；拖动超过 10px 即锁定方向 |
| 点选交换 | 点一颗 → 点相邻一颗     | 同左                 |
| 取消选择 | 点空白/再点自己        | 同左                 |
| 暂停   | `Esc` / 暂停按钮    | 暂停按钮               |
| 重开   | `R` / 报告页「再来一局」 | 同左                 |
| 洗牌   | 洗牌按钮；无路可走时自动洗   | 同左                 |
| 提示   | 提示按钮；每局 3 次     | 同左                 |

- 棋盘 `touch-action:none`，阻止 iframe 内滚动与双击缩放。

- 拖动时宝石跟随手指，偏移限制在半格内；松手未达阈值则回弹。

- 交换动画 150ms；无效交换回弹 160ms；动画期间锁输入，锁定时长不超过 180ms。

- 点选后相邻格显示淡色描边，避免误触。

- 键盘只在 iframe 聚焦时生效，关闭后随文档销毁。

### 5.7 计时、暂停与后台

- 计时从第一次**有效交换**开始，而不是进入棋盘时。

- 用 `performance.now()` 计算剩余时间，不依赖 setInterval 累加，避免后台节流导致时间漂移。

- `visibilitychange` 隐藏时自动暂停；回来后停在暂停层，玩家点「继续」再恢复。

- 暂停时棋盘不再绘制，音效全部停止。

- 步数模式不计时，暂停只用于查看盘面。

### 5.8 死局、洗牌与提示

- 每次落位结束后检查是否存在有效交换；不存在则在 500ms 后自动洗牌。

- 洗牌：保留当前宝石数量，重新随机排列，保证无初始三连且至少一步可走。

- 自动洗牌不消耗提示次数；手动洗牌每局最多 2 次。

- 提示：高亮一组可成线的交换，持续 1.5 秒；每局 3 次，不扣分。

- 无提示可用时按钮置灰，不弹错误。

### 5.9 每日鉴定

- 种子 = 本地日期 `YYYY-MM-DD` + 难度 `normal`，用 `mulberry32` 生成。

- 同一天、同一设备多次进入，盘面与补充序列一致。

- 每日盘固定 6 种品质、90 秒，不发金币；只更新每日最佳。

- 跨天后首次进入时重置每日盘；旧记录保留最佳分数。

- 连续参与天数记入本地成就，断签不清零总天数。

### 5.10 结算与记录

| 项    | 内容                              |
| ---- | ------------------------------- |
| 报告标题 | 「鉴定报告」                          |
| 主数据  | 本局分数、历史最佳、最高连锁、归位宝石数、鉴定镜 / 印章次数 |
| 新纪录  | 破纪录时盖章标记「新纪录」                   |
| 操作   | 再来一局 / 换模式 / 查看成就 / 返回百巴箱（外层 ✕） |
| 失败文案 | 「沙漏见底了，这一盘先记在这里。」               |
| 步数耗尽 | 「步数用完了，盘面已经记进报告。」               |

### 5.11 本地成就（8 条）

## 六、UI 与视觉规范

### 6.1 参考什么、改什么

**沿用（来自贪吃蛇 / 幸存者）：**

- 顶部 HUD：左侧标题，右侧分数 / 最佳 / 连锁小方块；

- 切角芯片（`clip-path`）、1px 细边 + 左侧 2px 高亮边；

- 等宽字体、`//` 前后缀小标签、四角光标框；

- 结算/暂停层的卡片式结构与按钮节奏；

- 分数弹跳、按钮按压缩放、低功耗一键降级。

**改掉：**

- `#031019 / #061c26` 深青底 → 暖象牙白；

- `#46e6f2` 青色主光 → 翡翠绿；

- 扫描线 / 暗角 → 极淡的纸面颗粒与柔和内阴影；

- 发光描边 → 细描边 + 轻投影，不做霓虹光晕。

> 结论：**结构像贪吃蛇/幸存者，气质像一间浅色珠宝鉴定台**。与飞行小游戏的「浅色冷青全息」也明确区分，不共用色板。

### 6.7 响应式与无障碍

- 分数、剩余时间、步数均有文本，不只靠图形。

- 尊重 `prefers-reduced-motion`：关闭震屏、粒子、扫光，保留必要位移。

## 七、音效

- 全部用 Web Audio API 合成，复用「单一 AudioContext + 总输出限幅 + 单音音量钳制 + 并发上限 + 节点释放」的既有规范。

- 不引入音频文件；静音开关读主存档 `muted`，本作不另存。

- 低功耗模式**不影响音效**，只关视觉特效（与主游戏规则一致）。

| 事件      | 音色方向                  |
| ------- | --------------------- |
| 交换      | 短促木质「嗒」               |
| 无效交换    | 低一档的闷响                |
| 三连      | 清亮的上行两音               |
| 连锁      | 随 chain 升调，chain 越高越亮 |
| 鉴定镜     | 短扫弦 + 高频闪光            |
| 品质印章    | 低频落印 + 同品质共鸣三音        |
| 洗牌      | 一串轻快的错落音              |
| 提示      | 柔和双音                  |
| 开始 / 结算 | 克制的三音动机，不用长混响         |
| 按钮      | 轻点                    |

- 同帧大量消除时，按 120ms 前缘节流合并，避免并发撑满变成噪音。

## 八、数据与存档

### 8.1 独立存档

```js
const SAVE_KEY='yueba-bejeweled-v1';
{

  best:{easy:0,normal:0,hard:0,moves:0,daily:0},
  clear:{easy:false,normal:false,hard:false,moves:false},
```

- 读档做结构归一化，字段缺失/类型异常自动补默认值，不允许报错。

- 主存档只读：`lang / muted / lowPower`，绝不写入 `idle-yueba-save-v2`。

### 8.2 语言

- 优先级：`?lang=` → 主存档 `lang` → 浏览器语言（ja/ko/en，其余 zh）。

- 页内 `T` 字典覆盖全部文案；切换语言只重绘可见层，不重开对局。

- 品质名、模式名、成就名、月巴台词全部四语言齐全。

### 8.3 奖励（首版关闭）

- 首版不发送任何金币，不写主存档。

- 预留 `postMessage({type:'yueba-bejeweled-coins', coins, id})`；父页监听需校验 `origin`，并做上限钳制（建议 5,000）。

- 若要开启：建议各难度首次达标发 60 / 120 / 200 金币，重复通关不发；接入时再加 `message` 分支与 toast，不改子页存档结构。

### 12.1 实装前（M1–M4）

### 12.2 入口与关闭（M5）

1. 百巴箱出现「宝石月巴」卡片，图标为钻石月巴；点击打开 iframe，标题「🎁 宝石月巴」。

4. 图鉴详情页出现「💎 进入宝石月巴」。

### 12.3 核心玩法

1. 开局盘面无三连、至少一步可走；连续开 20 局均满足。
2. 拖动/点选均可交换；无效交换回弹且不扣步数；动画锁输入不超过 180ms。
3. 三连、四连、五连、L/T 形均按规则生成/消除；连锁倍率与上限 ×5 正确。
4. 4 连鉴定镜清整行/列；5 连品质印章清全盘同品质；两者再次参与成线可触发。
5. 死局 500ms 内自动洗牌，洗完仍有解；手动洗牌每局 2 次。
6. 提示高亮一组有效交换，持续 1.5 秒，每局 3 次；用完后按钮置灰。
7. 限时 90 秒、限步 25 步、每日 90 秒均可正常结束并出报告。
8. 每日鉴定同日同盘，跨天刷新；每日不发金币。

### 12.4 视觉与交互

1. 360×640、390×844、桌面 1280×800 下均不溢出；棋盘 ≥ 40px/格。
2. 浅色配色可读，宝石颜色+外形+符号三重区分；不出现深青全息底色。
3. 交换 1:1 跟随、消除/连锁反馈清晰；低功耗与 `prefers-reduced-motion` 下特效关闭但不影响游玩。

5. 四语言切换后标题、模式、品质名、成就、月巴台词均正确，无空白/undefined。

### 12.5 稳定性与性能

1. 切后台自动暂停，回来自动停在暂停层；计时不漂移。
