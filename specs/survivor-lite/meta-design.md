# 番茄幸存者 · 关卡之外设计文档

> 定位：本文只讨论「进入战斗之前 / 之后」的局外与流程设计——入口、模式、角色、难度、局外成长、收藏记录、成就、每日 / 周常、跨游戏联动、设置与存档。
> 战斗内的武器、遗物、敌人、机关与关卡数值见 `plan4.md` 与 `spec-c1-forest.md`，本文只在接口处提及。
> 现状基于 `survivor.html` 与 `index.html` 当前实现（14 关、28 件遗物、4 角色、3 难度、6 件装备）。

---

## 一、现有设计盘点

### 1.1 入口与页面地图

| 入口 / 页面 | 位置 | 现有功能 | 状态 |
|---|---|---|---|
| 首页入口 | `index.html` → `#btnSurvivor` / `survivorEntry()` | 先落盘再跳转 `survivor.html` | `SV_PUBLIC=false`，仅 `#debugall` 可见 |
| 开始页 | `lyStart` | 模式、角色、难度、关卡列表、装备、图鉴、统计、圣所、开始、返回首页 | 完整 |
| 暂停页 | `lyPause` | 当前构筑摘要、继续、退出到标题 | 完整 |
| 结算页 | `lyResult` | 存活 / 击杀 / 等级、金币与掉落、构筑、小说解锁位 | 小说位为空占位 |
| 宝物图鉴 | `lyCodex` | 28 件按稀有度分组，已见 / 已获得计数 | 完整 |
| 统计页 | `lyStats` | 场次、胜场、总击杀、宝箱、宝物种类、无尽最佳、各关最快 | 11.x 最快记录读不到 |
| 圣所 | `lySanct` | 4 项永久强化，金币购买 | 完整 |
| 装备配置 | `lyGear` | 6 槽位、已拥有装备切换 | 完整 |
| 未开放 | `gate` | 非公开 / 非调试时拦截 | 完整 |

开始页的信息密度较高：一屏内同时承载 4 个选择维度（模式 / 角色 / 难度 / 关卡）+ 装备 + 三个次级入口。新手第一次进入会在 10 个以上按钮里迷路，这是当前最明显的体验问题。

### 1.2 局外成长

**金币（幸存者独立货币）**

- 独立记账：存放在 `save.svCoins`，与首页 `save.coins` 不互通；来源为结算奖励。
- 胜利公式：`(400 + 关卡n×200 + 首通本关 200×n) + 击杀×2 + 等级×60 + 存活秒×3 + 首胜1200`，再乘角色 / 难度 / 遗物金币乘区。
- 失败局只有 `击杀×2 + 等级×60 + 存活秒×3`，没有保底。
- 出口目前只有圣所。

**圣所**

| 项 | 每级 | 上限 | 起价 | 封顶 | 满级总投入 |
|---|---|---|---|---|---|
| 生命 | 最大生命 +5 | 10 | 400 | 12,000 | 72,400 |
| 伤害 | 伤害 +2% | 10 | 500 | 15,000 | 90,500 |
| 幸运 | 拾取 +2% | 10 | 300 | 9,000 | 54,300 |
| 重抽 | 每局重抽 +1 | 3 | 2,000 | 30,000 | 14,000 |

合计约 23.1 万金币。按单局 4,000–6,000 金币计算，老四项满级约需 40–55 局。

**解锁链**

| 内容 | 条件 | 现状评价 |
|---|---|---|
| 樱桃 / 牛排 / 金番茄 | `stageClear` ≥ 2 / 4 / 6 | 前 6 关内全部解锁，偏快 |
| 困难 / 噩梦 | `stageClear` ≥ 3 / 6 | 与角色解锁重叠 |
| 无尽模式 | `stageClear` ≥ 6 | 合理 |
| 装备掉落 | 通关 `playableCount()`，当前为 11.4 | 6 件装备需要重复通 11.4 六次 |
| 11.x 关卡 | 前置关卡首通 | 正常 |

**装备（跨游戏加成）**

6 件装备、6 槽位，加成只作用于首页旅行：旅行时长、信件配额、特产概率。当前只在「当前最终关」掉落，第四层全部做完后会变成 14.4，掉落点还会继续后移。

### 1.3 收藏与记录

- **宝物图鉴**：28 件，分组显示；未见显示 ❔，已获得显示累计次数。分母跟随 `RELICS.length` 自动变化。
- **统计**：6 个总览指标 + 各关最快。各关最快读取键为 `'' + st.n`，而 11.x 实际存档键是 `'11.1'`，因此 11–14 关始终显示 `—`。
- **关卡最佳**：按 `st.key`（1–10 为数字字符串，11+ 为 `'11.1'`）再叠加 `:hard` / `:nightmare` 分键。
- **无尽**：最佳存活时长、最佳击杀。
- **成就**：`index.html` 中 `sv1–sv10`，其中 `sv8` 为本轮新增（首通 11.1）。成就在首页弹窗展示，没有金币奖励。
- **小说解锁位**：`NOVEL=[]`，结算页始终显示「正文尚未录入」，正反馈落空。

### 1.5 跨游戏联动

| 联动方向 | 现状 |
|---|---|
| 金币 | 各自独立：幸存者存 `save.svCoins`，结算写回、圣所消耗，均不触碰首页 `save.coins` |
| 装备 → 旅行 | 首页 `svGearBonus()` 读取 `survivor.gear.bonus`，影响旅行时长 / 信件 / 特产 |
| 结算礼物 → 首页收藏 | `applyRewards` 把 `GIFT_POOL` 掉落写入 `save.collection` |
| 成就 | 首页成就系统读取 `S.survivor.clears / stageClear / relics` |
| 地图主题 | 11–14 对应森林四图，与首页旅行地图的森林主题、皮肤解锁链同源 |
| 存档 | `localStorage` + IndexedDB 文件句柄镜像，双端共用 `idle-yueba-save-v2` |

已经形成「幸存者出装备 → 旅行更顺 → 解锁地图与信件 → 反过来强化幸存者关卡主题」的闭环雏形，但目前只有装备一条真实链路（金币已拆为独立货币，不再参与跨游戏联动），叙事和地图解锁还没有互相引用。

## 三、设计建议

### 3.1 P0 · 一致性与低成本修复

1. **统计页读取键**：`renderStats` 改用 `bestKey(st.n, 'normal')`；已在 `stageBest` 里的困难 / 噩梦记录可加第二行小字，或只显示普通。
2. **成就口径重排**：
   - `sv7` 保留「通关前 10 关」，文案改为「完成前 10 关」而非「全部关卡」。
   - `sv9` 阈值改为 28（或统一改为 30，与 plan4 对齐），文案同步。
   - 新增 `sv11` = 通关 11.4、`sv12` = 通关 14.4，给后续四层留出成就位。
3. **装备掉落重做**：从「当前最终关」改为「每层最后一图首通掉 1 件 + 每层四图全清额外 1 件」。
   - 6 件装备的期望获取点：11.4、12.4、13.4、14.4 首通各 1 件，四图全清宝箱再补 2 件。
   - 这样扩层时掉落点自动跟随，不需要每次改常量。
4. **小说位处理**：在正文录入前，结算页不渲染「小说解锁位」；或先放 1 段 11.1 的短文，把「解锁」的仪式感做出来。
5. **设置面板最小版**：只做 4 项——音效开关、震屏、粒子、语言。先把已有字段接上，音量条与色弱可以后置。

### 3.2 P0 · 局外闭环

当前局外只有「金币 → 圣所」一条线，建议补成三条：

| 出口 | 设计 | 目的 |
|---|---|---|
| 圣所扩线 | 护甲 / 磁力 / 开局重抽，总投入约 10 万 | 消耗后期金币，提供可感知的数值成长 |
| 成就奖励 | 每个 `sv` 成就一次性发放 200–2,000 金币 | 让成就从展示变成正反馈 |
| 图鉴里程碑 | 见闻 10 / 20 / 30 / 40 种各发一次奖励 | 鼓励尝试不同遗物，而不是只拿强势组合 |

同时建议给失败局一个低成本保底：`max(80, 击杀×2 + 存活秒×2)`，不乘难度金币。避免「打了 12 分钟失败一无所获」直接关游戏。

### 3.3 P1 · 新手目标与首屏减负

- 开始页顶部放「下一个目标」单行提示，按进度三选一：
  1. 首通 1 关 → 解锁樱桃；
  2. 首通 3 关 → 解锁困难；
  3. 首通 6 关 → 解锁无尽。
- 模式 / 角色 / 难度收进一条可折叠的「配置」区，默认只显示当前选择，点击展开。关卡列表保持一级可见。
- 结算页增加「下一目标」与「推荐关卡」，让失败局也有明确的下一步。

### 3.4 P1 · 重玩价值

按投入产出排序：

1. **每日挑战**：固定种子 + 固定角色 / 关卡 / 难度，每天 1 次。实现成本最低，重玩收益最高。计分建议：`击杀×10 + 存活秒×5 + Boss波次×500 + 胜利3000`，金币 `分数/20`，首通额外 1,000。
2. **无尽词缀**：每 2 轮 Boss 抽 1 条，最多 4 条。它复用现有 Boss 循环，只加乘区与结算展示。
3. **Boss Rush**：连续 5 Boss，间歇回血 30% + 三选一。复用第 3 / 6 / 9 / 10 关 Boss，主要成本在流程状态机。
4. **回响难度**：每图通关后解锁，敌人 +1 档，独立记录键 `'11.1:echo'`，给高玩一个长期目标。建议放到 12–14 层全部完成之后再做。

不建议做「每日签到 / 体力 / 限时活动」，这与本作「想玩就玩一局」的定位冲突。

### 3.5 P1 · 装备与跨游戏联动

- **获取节奏**：见 3.1 第 3 条。装备总量可以维持 6 件，但建议按 2 件一组分三层掉落，让旅行加成逐步成型。
- **套装效果**：2 件 / 4 件各给一条轻量效果（例如 2 件：信件 +5%；4 件：旅行 -5%），在装备页显示激活状态。
- **反向联动**：旅行侧解锁的森林 / 小镇 / 大海 / 雪地主题，可在幸存者侧解锁对应关卡手记或结算配色，但不影响数值，避免「不玩旅行就打不过」。
- **货币纪律**：继续只保留金币一种跨游戏货币，不做幸存者专属代币。

### 3.6 P2 · 叙事与展示

- **关卡手记 `mapIntro`**：每图 3 段（入场 / 50% / 95%），第一次触发时以横幅或暂停式小卡展示，之后进图鉴可回看。成本低，能显著提升 11 层之后的「旅途感」。
- **小说正文**：`NOVEL` 至少填 1 篇，并按 `stageClear` 解锁后续篇章，替代当前的空占位。
- **角色熟练度 / 称号**：只给配色与结算称号，不给数值，避免练度焦虑。
- **结算分享卡**：生成一段可复制的文本（角色 / 难度 / 关卡 / 时长 / 击杀 / 构筑），或 Canvas 截图。无需后端。
- **本地榜**：无尽前 5、每日前 5。数据只存本地，不做在线排行。

### 3.7 P2 · 设置、可访问性与移动端

- 设置项：音效 / 音乐音量、震屏、粒子、伤害数字、语言、色弱标记、HUD 缩放。
- 首次进入若 `prefers-reduced-motion` 开启，默认关闭震屏与粒子。
- 移动端：右下角主动技按钮、轻震动（可关）、暂停时自动降低粒子。
- 手柄与按键重绑放到最后，优先级低于每日与设置。

### 3.8 不建议做

| 项 | 原因 |
|---|---|
| 体力 / 每日签到硬绑 | 与单局 roguelike 的节奏冲突 |
| 付费抽卡 / 数值付费 | 单机定位，且会破坏局内构筑公平 |
| 多货币体系 | 现有金币已够用，多币种只会增加理解成本 |
| 局外永久数值过强 | 会稀释局内三选一的决策权重 |
| 在线排行榜后端 | 维护成本高，本地榜足够 |

## 四、经济与节奏建议

| 项目 | 现状 | 建议 |
|---|---|---|
| 单局金币（胜利） | 约 4,000–6,000 | 保持 |
| 单局金币（失败） | 仅击杀 / 等级 / 时长 | 增加 `max(80, 击杀×2 + 存活秒×2)` |
| 圣所总投入 | 约 23.1 万 | 新增 3 项后约 33 万，满级约 60–70 局 |
| 角色解锁 | 2 / 4 / 6 关 | 若希望 11 层后仍有目标，可改为 2 / 5 / 9；否则保持 |
| 装备获取 | 仅当前最终关 | 每层最后一图首通 + 四图全清宝箱 |
| 每日奖励 | 未实现 | 分数 / 20，首通 +1,000 |
| 成就奖励 | 无 | 200–2,000 / 个，一次性 |

设计原则：**金币只买「让下一局更舒服」的东西，不买「让这一局必胜」的东西。** 圣所全部是软性成长，符合这个原则；新增项也应保持同一尺度。

## 五、建议落地批次

| 批次 | 范围 | 依赖 |
|---|---|---|
| 5A · 一致性修复 | 统计键、成就阈值与文案、装备掉落、小说位隐藏、设置面板最小版 | 无 |
| 5B · 局外闭环 | 圣所扩线、成就奖励、图鉴里程碑、失败保底 | 5A 的存档字段 |
| 5C · 重玩模式 | 每日挑战、无尽词缀、Boss Rush | 5A 的随机源与记录结构 |
| 5D · 叙事与展示 | 关卡手记、小说正文、熟练度、分享卡、本地榜 | 5B / 5C |
| 5E · 内容扩充 | 12 小镇 / 13 大海 / 14 雪地 四图 ×3，地图武器与遗物扩到 40 | 5C 的模式框架 |

建议先做 5A：全部是局部修复与小面板，风险最低，但能立刻修正「新关卡记录看不到」「装备要刷六次 11.4」「成就文案过期」三个明显问题。

## 六、验收口径

1. 新档 30 分钟内：首通 1 关、解锁 1 个角色、见过至少 6 件遗物。
2. 任意通关 11.1 后：统计页显示 11.1 的最快时间；存档键为 `'11.1'`。
3. 装备调整后：11–14 层自然获取 6 件，不需要重复刷同一关。
4. 成就：`sv7` / `sv9` 文案与实际阈值一致；`sv11` / `sv12` 可正常解锁。
5. 结算页：未录入小说正文时不出现空占位。
6. 设置面板：音效开关、震屏、粒子、语言四项即时生效，刷新后保留。
7. 失败局：金币不为 0，且不高于同等时长胜利局的 60%。
8. 四语言、静音、低功耗开关不回归。

## 七、风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| 双端写存档互相覆盖 | 首页与幸存者页都写 `save.coins` | 每次写前重新 `readSave()`，写后立即 `IDX = save` |
| 金币膨胀 | 新增成就奖励与图鉴奖励会抬高收入 | 奖励一次性、总额封顶；新圣所费用同步提高 |
| 内容稀释 | 一次加太多模式会让每模式都浅 | 按 5C 顺序逐个上线，每个模式先做最小闭环 |
| 移动端性能 | BGM、伤害数字、更多粒子叠加 | 低功耗默认关闭伤害数字与 BGM 高频层 |
| 叙事与玩法脱节 | 手记 / 小说写完没人看 | 只在首通与里程碑弹出，不打断战斗 |
| 旧档迁移 | v3 → v4 字段增多 | 只增字段、缺什么补什么，启动时写回一次 |
