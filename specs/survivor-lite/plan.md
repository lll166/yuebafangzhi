## 三、玩法设计（Day 1 范围）

### 3.1 核心循环

| 模块 | 规则 | 备注 |
|---|---|---|
| 主角 | 🍅 番茄；HP 100；移速 220；受击后 0.6s 无敌 + 闪白 | 圆形象征，程序化绘制 |
| 操作 | WASD / 方向键；移动端左下虚拟摇杆；自动瞄准最近敌人 | 不需要鼠标瞄准 |
| 攻击 | 「番茄籽」自动射击；间隔 0.45s；伤害 3；弹速 560；寿命 1.6s | 首版单武器 |
| 敌人 | 普通/快速/坦克/精英 4 类，复用 `TYPES`/`TYPES2` 的颜色与形状 | 优先用站内 `img` 的 13 张月巴立绘；加载失败回退程序化形状 |
| 立绘绘制 | 立绘本体接近纯白，直接画在深色场地会糊成白斑 | 先铺暗色径向底盘（`rgba(16,12,28,.95→0)`，半径 `1.4r`）压住背景，再叠 22% 主题色盘面 + 90% 主题色外环（线宽 `max(1.6, .16r)`），白色立绘才有轮廓 |
| 敌人 AI | 直线朝玩家移动；接触造成伤害；受击闪白；死亡掉 XP | 不做寻路，保持简单 |
| 经验 | XP 宝石掉落；90px 磁吸；升级弹出 3 选 1 | 升级时暂停 |
| 升级池 | 8 项：伤害 ×1.2（≤8 层）、射速 ×0.85、移速 ×1.1、最大 HP +20、拾取 ×1.25、多重弹 +1、弹速 ×1.12、回血 +30 | 可叠加，多数设上限；回血不设上限 |
| 波次 | 环形刷怪；刷新率随时间升高；同屏上限 180 | 数量到上限时暂停刷新而不是卡帧 |
| 精英 | 每 60s 一名，血量/体型更大，掉更多 XP | 作为节奏节点 |
| Boss | 5:00 登场（名字「归家月巴」）；HP 1200；接触伤害 25；每 8s 召唤小怪 | 击败即胜利；6:00 后 Boss 未死则继续 |
| 场景 | 单屏竞技场，不跟随相机；逻辑坐标 1280×720，等比缩放 | 降低首版复杂度 |
| 失败 | HP 0 → 结算；可「再来一次」 | 不解锁小说 |

### 3.2 单局节奏

| 时间 | 体验目标 | 内容 |
|---|---|---|
| 0:00–1:00 | 学会移动与自动攻击 | 慢速小月巴，少量 |
| 1:00–3:00 | 第一次升级选择 | 刷新加快，出现快速敌人 |
| 3:00–5:00 | 压力峰值 | 坦克 + 精英混编 |

## 四、小说解锁位（首版预留）

> 小说正文暂未提供。首版**没有实现书架、打字机和逐章解锁**；只在胜利结算页显示「小说正文尚未录入」占位，并在存档中保留 `S.survivor.unlocked/read` 字段。补正文后按下面的结构接入即可。

### 4.1 数据定义

```js
// 只定义结构；正文由你提供，先用占位段落跑通流程
const SV_NOVEL = [
  { id:'ch01', title:'第一章 · 暂定标题', unlockAt:1, body:['段落一…','段落二…'] },
  { id:'ch02', title:'第二章 · 暂定标题', unlockAt:2, body:['段落一…','段落二…'] },
];
```

- `unlockAt`：第几次胜利解锁；首版按「通关次数」顺序解锁。
- 正文不放结算弹窗硬编码里；结算页只读取 `SV_NOVEL`。
- 多语言用章节 id 取译文，缺译文回退中文：
  `I18N_SV_NOVEL = { ch01:{ title:{en,ja,ko}, body:{en:[],ja:[],ko:[]} } }`

### 4.2 流程

| 环节 | 行为 | 数据变化 |
|---|---|---|
| 胜利 | 显示「胜利」+ 本局统计 | `clears++`、`bestTime/bestKills` 更新 |
| 解锁 | 取 `unlockAt === clears` 的章节；若已全部解锁则显示「全章已收录」 | `unlocked[chId]=true` |
| 展示 | 结算页内打字机逐段显示；可「跳过」 | 不改状态 |
| 收录 | 点击「收录」后标记已读 | `read[chId]=true` |
| 回看 | 开始页「📖 小说」进入书架；点章节进入阅读层 | 阅读不重复解锁 |
| 提示 | 未读章节显示 `NEW` 红点；书架显示 `已收录 n/总数` | 依据 `read` |

### 4.3 存档结构

```js
S.survivor = {
  v: 1,
  clears: 0,
  bestTime: 0,
  bestKills: 0,
  unlocked: {},   // ch01:true
  read: {},       // ch01:true
  seenIntro: false
};
```

`load()` 中必须单独深合并：

```js
S.survivor = Object.assign(defaultState().survivor, d.survivor || {});
S.survivor.unlocked = Object.assign({}, (d.survivor||{}).unlocked);
S.survivor.read = Object.assign({}, (d.survivor||{}).read);
```

否则老存档读入后 `unlocked/read` 可能变成 `undefined`。

## 五、技术方案

### 5.1 页面结构

`survivor.html` 是独立单文件页面，内部分层：

```html
<canvas id="cv"></canvas>
<div id="hud">…HP / 计时 / 击杀 / 等级 / 暂停…</div>
<div class="layer" id="lyStart">…标题、开始、返回首页…</div>
<div class="layer" id="lyLevel">…3 选 1…</div>
<div class="layer" id="lyPause">…暂停…</div>
<div class="layer" id="lyResult">…胜负、统计、奖励、小说占位…</div>
<div class="layer" id="gate">…非调试访问时的未开放提示…</div>
<div id="debugbar">…仅 #debugall 显示…</div>
```

- 游戏固定逻辑坐标 1280×720，等比缩放到视口，使用 `contain` 留边。
- 移动端竖屏提示「建议横屏游玩」；横屏可完整铺开。
- 退出游戏通过链接回到 `index.html#debugall`，保留调试入口。
- 未来若改成首页内嵌：`index.html` 增加全屏覆盖层，用 `<iframe src="survivor.html#debugall">` 加载本页即可，游戏代码无需改动。

### 5.2 游戏循环

```js
function svLoop(t){
  sv.raf = requestAnimationFrame(svLoop);
  const dt = Math.min(0.05, (t - sv.last)/1000);
  sv.last = t;
  if (sv.paused || document.hidden) { svRender(); return; }
  svUpdate(dt);
  svRender();
}
```

- 固定步长 1/60 累积，单帧最多追 3 步，避免切后台回来瞬移。
- 退出必须：`cancelAnimationFrame`、移除键盘/指针监听、移除 `sv-lock`、清空对象池。
- 低功耗模式：降低粒子、关闭拖尾与阴影、DPR 上限 1.5。

### 5.3 性能约束

| 项 | 约束 |
|---|---|
| 同屏敌人 | ≤ 180 |
| 同屏子弹 | ≤ 120 |
| 同屏 XP 宝石 | ≤ 150，超出合并/自动拾取 |
| 渲染 | Canvas 2D；不用 DOM 实体 |
| 对象池 | 敌人、子弹、宝石、飘字全部池化 |
| 碰撞 | 圆形碰撞 + 距离平方；必要时用网格分区 |
| DPR | `Math.min(devicePixelRatio, 2)` |
| 后台 | `visibilitychange` 自动暂停 |
| 低功耗 | 粒子减半、无阴影、帧率可不锁 |

### 5.4 输入

- 键盘：`keydown/keyup` 维护方向集合；仅 `#survivor.show` 时生效；`ESC` 暂停；阻止方向键滚动。
- 触屏：左下虚拟摇杆（按下位置为圆心，最大半径 48px），松手归零。
- 自动瞄准：最近敌人；无敌人时朝移动方向。
- 所有监听在 `svExit` 里移除，避免影响主页面的旅行/飞行键盘逻辑。

### 5.5 入口与开关

```js
const SV_PUBLIC = false; // 上线开关：调试期保持 false
function svVisible(){ return SV_PUBLIC || DR_DEBUG; }
function updateSurvivorIcon(){
  const el = $('btnSurvivor');
  if (el) el.style.display = svVisible() ? '' : 'none';
}
```

- `init()` 调用一次；`#debugall` 分支里再调用一次（因为 `DR_DEBUG` 在 init 后段才置位）。
- 普通玩家：无 hash → 按钮不存在；`#debugall` → 按钮出现。
- 可选深链：仅调试期支持 `#debugall` + `#survivor` 自动进入；不要做普通玩家可用的深链。

### 5.6 调试工具（仅 `DR_DEBUG`）

```js
window.svDebug = {
  win(){...}, lose(){...}, unlockAll(){...}, reset(){...},
  god(){...}, setTime(sec){...}, spawn(type){...}
};
```

- 用于快速验收小说解锁、Boss、结算、书架。
- `reset()` 清空 `S.survivor`，方便重复测试。

### 5.7 音效、皮肤、i18n

- 音效：复用 `tone()` / `sfx`，遵守 `S.muted`；同帧同类音效做节流（参考飞行/斗月巴）。
- 皮肤：不为 21 套皮肤各写一套游戏皮肤。外框走 CSS 变量；Canvas 内部用固定高对比配色（番茄红 / 月巴紫 / 奶油底）。
- i18n：UI 文案进 `I18N_UI`；小说正文走章节 id 表；未翻译时 `$t` 天然回退中文。
- 新增中文串后运行 `node specs/i18n/extract-strings.mjs` 盘点，再补 en/ja/ko。

### 5.8 文件组织

- 全部内嵌在 `index.html`，用清晰分区包裹：
  `/* ===== 番茄幸存者 START ===== */` … `/* ===== 番茄幸存者 END ===== */`
- 首版预计 1200–1800 行；若超过 2500 行或需要单独调试，再拆 `survivor.js`。
- GitHub Pages 支持多文件，但单文件更方便本地双击打开与备份；先内嵌。

## 七、相关意见（重点）

1. **先做闭环，不做全套。** 参考项里的 11 个系统是骨架，不是首版清单。首版只保留「移动 + 自动射击 + 刷怪 + 升级 + Boss + 小说」；多武器、进化、局外成长全部后置。
2. **入口用代码开关，不要靠注释。** 统一走 `SV_PUBLIC || DR_DEBUG` 和 `updateSurvivorIcon()`；不要在两个地方各写一遍显示逻辑，否则以后很容易漏删调试代码。
3. **小说是奖励层，和玩法解耦。** 结算页只负责「取章节 → 展示 → 标记已读」；章节内容、解锁顺序都放 `SV_NOVEL`。以后加章节不改战斗代码。
4. **正文请你提供。** 我可以先放 3 段占位把流程跑通，但不代写正文，避免和你已有小说的文风、设定、版权冲突。
5. **首通要偏简单。** 小说解锁是正反馈；如果 6 分钟太苦，玩家看不到奖励就流失。Boss 更建议做成「演出型」：血厚、招式少、有召唤，但不做秒杀。
6. **奖励直接写回首页存档，别再让玩家手动领。** 首版采用「游戏结算时直接修改同一个 localStorage 存档」：金币加到 `coins/totalCoins`，图鉴记录加到 `collection`，`S.survivor` 记录通关数；成就由首页 `checkAch` 在下次加载时自动结算。注意调试期 `#debugall` 会把金币重置为 999999999，所以调试时看到的金币余额不代表真实奖励，但 `totalCoins`、图鉴记录与成就仍会保留。
7. **用 Canvas，不要用 DOM 堆怪物。** 上百个月巴 + 子弹 + 宝石时，DOM 的布局与重排会拖垮帧率；Canvas + 对象池更稳。
8. **不要为 21 套皮肤做 21 套游戏皮肤。** 外框跟随皮肤变量即可，Canvas 内部用固定的番茄红/月巴紫/奶油底。否则维护成本会指数上升。
9. **手机端必须有虚拟摇杆。** 只支持 WASD 等于放弃移动端；自动瞄准可以大幅降低操作门槛。
10. **游戏本体独立成页，index 只做入口。** 这样 index 不会被游戏代码继续撑大，也方便以后单独调试/替换；如果以后要求「不离开首页」，再加全屏覆盖层 + iframe 加载 `survivor.html`，游戏代码不用改。
11. **存档要深合并。** 现有 `load()` 是浅合并；`S.survivor` 里的 `unlocked/read` 必须单独补默认值，否则老档读入后写 `unlocked[ch]` 会直接报错。
12. **退出清理是硬要求。** 参考飞行游戏的 `flyExit`：取消 rAF、移除监听、移除 body 锁。否则主页面方向键、空格、滚动都会被游戏劫持。
13. **i18n 先 UI、后正文。** UI 四语补齐；小说正文允许中文回退，等正文定稿后再补 en/ja/ko。不要为了翻译卡住玩法。
14. **玩法可参考，素材不要复制。** VS-lite 是 MIT，但它是 Unity/C#；我们只借鉴系统划分。月巴形象用站内现有 `img` 或程序化形状，音效走现有 `tone()`。
15. **把「普通玩家看不到」写进验收。** 分别测试：无 hash、`#debugall`、刷新后、切换 `SV_PUBLIC` 四种情况。
