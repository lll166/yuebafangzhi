# 番茄幸存者 · Plan 4（体验收尾 + 构筑扩展 + 内部优化）

> 前置：Plan 1（独立页 + 奖励/成就/立绘）、Plan 2（6 关 + 8 事件 + Boss 三阶段 + 18 遗物）、Plan 3（10 关 + 副武器/进化 + 角色/难度/无尽/图鉴/圣所 + 存档 v3）已落地。
> 本文档回答两件事：**Plan 4 还能扩什么内容**、**游戏内部还欠哪些工程债**。
> 原则不变：单文件 `survivor.html`、Canvas 2D、逻辑坐标 1280×720；只借鉴成熟 Survivor-like 的结构，不复制素材与数值。

| 项 | 内容 |

## 三、扩充方向

### 3.1 构筑深化（4B · P1）

#### 3.1.1 两把地图副武器（11 / 12 层）

> 10 层之后的武器不再进通用池，而是从对应旅行地图里获得；拿到后写入蓝图，之后所有关卡都能在升级池里抽到。

| id | 名称 | 来源地图 | 机制 | 每级成长 | 上限 |
|---|---|---|---|---|---|
| `pinecone` | 松果弹弓 | 11.1 森林边缘 | 向最近敌人抛出松果，落点 42px 爆炸，可越过前排 | 爆炸半径 +4，伤害 +3，Lv5 同时抛 2 颗 | 5 |
| `lantern` | 兔子灯 | 12.2 月光夜市 | 一盏兔子灯绕玩家缓慢旋转，碰到敌人点燃并留下 1.2s 火痕 | 灯 +1（Lv3 / Lv5），伤害 +2，火痕 +0.3s | 5 |

数值起点：

```js
pinecone : cd 1.7s, 射程 300, 爆炸半径 42, dmg 14
lantern  : 1 盏, 半径 64, 转速 1.6rad/s, dmg 6, 火痕 6/s
```

设计意图：现有三把都是「贴身/自动」型，补一把「中距离投掷」和一把「移动火源」，让走位与站位更有意义。13 / 14 层的两把地图武器见 3.4.4。

#### 3.1.2 两条地图进化

| 进化 | 条件 | 效果 |
|---|---|---|
| 森罗万象 | `pinecone` Lv5 + 11 层遗物「萤火灯」 | 爆炸留下 2.5s 萤火地带，范围内敌人持续受伤并显形 |
| 万家灯火 | `lantern` Lv5 + 12 层遗物「夜市灯」 | 兔子灯 +1，火痕扩大 30%，击杀 15% 概率再点亮一盏（上限 5） |

- 进化卡继续金色边框 + 「进化」标签。
- 进化后名称、弹体颜色、命中音效全部替换。
- 不新增槽位，仍占原武器槽。

#### 3.1.3 遗物改为地图专属（24 → 40）

Plan 3 的通用遗物已经够用，Plan 4 不再加通用遗物，改为 16 件「一图一件」的地图遗物（见 3.4.5）。

原草案里的 6 件通用遗物（磁力皮 / 锋利皮 / 回声 / 霜核 / 藤心 / 守护壳）拆解进地图遗物效果，避免卡池被稀释。

#### 3.1.4 遗物标签与共鸣

给 40 件遗物加 `tag`：`烈焰 / 寒霜 / 连锁 / 守护`。

| 条件 | 共鸣效果 |
|---|---|
| 同标签 2 件 | 该标签主题小加成（伤害 +5% / 减速 +8% / 跳距 +20 / 护盾恢复 +10%） |
| 同标签 4 件 | 主题强化（进化武器伤害 +10%，或护盾破碎时爆炸） |

- 只做两档，避免变成套装刷子。
- 标签与进化有交叉，但不强制：进化仍是「武器 Lv5 + 指定遗物」。

#### 3.1.5 开局种子三选一

每局开始从 3 张「种子卡」中选 1：

```js
{ type:'relic', id:'pierce' }        // 直接给 1 层遗物
{ type:'weapon', id:'orbit' }        // 直接给副武器 Lv1
{ type:'stat', key:'dmg', v:0.10 }   // 本局伤害 +10%
```

- 只在开始页展示，不暂停战斗。
- 与角色起始武器叠加；若角色已自带该武器，则自动换成同池其它卡。
- 目的：让第一分钟就有构筑方向，减少「前 3 次升级全是移速/拾取」的挫败。

#### 3.1.6 诅咒遗物（困难/噩梦限定）

| id | 名称 | 正面 | 负面 | 上限 |
|---|---|---|---|---|
| `berserk` | 狂血 | 伤害 +35% | 最大生命 −25% | 1 |
| `greedcursed` | 贪婪之胃 | 金币 +50% | 敌人移速 +12% | 1 |
| `glasscannon` | 玻璃核 | 射速 +30% | 受到伤害 +20% | 1 |
| `nightowl` | 夜枭 | 幸运 +30% | 视野边缘变暗（仅表现） | 1 |

- 只在困难/噩梦的宝箱或 Boss 奖励中出现，红色卡面。
- 不与现有 `glass`（玻璃番茄）叠加超过 2 件，避免数值失控。

### 3.3 模式扩展（4C · P1）

#### 3.3.1 每日挑战

| 项 | 规则 |
|---|---|
| 解锁 | 通关第 3 关 |
| 固定项 | 日期种子、关卡（`day % 10 + 1`）、角色（按日轮换）、难度（工作日普通/周末困难） |
| 次数 | 每天 1 次；退出或失败即消耗 |
| 计分 | `击杀 × 10 + 存活秒 × 5 + Boss 波次 × 500 + 胜利 3000` |
| 记录 | `daily.best`、`daily.day`、本地前 5 名 |
| 奖励 | 金币 = `score / 20`，每日首通额外 1000 |

实现要点：

- 新增 `SEED` 随机源，`rand()` 在每日模式改用 `mulberry32(hash(day))`。
- 敌人出生、升级卡、宝箱、事件全部走同一随机源，保证同一天同流程。
- 结算页显示「今日排名 / 本地最佳」。

#### 3.3.2 Boss Rush

| 项 | 规则 |
|---|---|
| 解锁 | 通关第 10 关 |
| 流程 | 连续 5 个 Boss，每个 Boss 60–90 秒；中间不刷普通怪，只刷少量随从 |
| 间歇 | 每个 Boss 后回血 30%，三选一强化（不暂停计时） |
| 失败 | 任一 Boss 未击败即结束 |
| 记录 | 总用时、击败数、最高连击 |
| 奖励 | 金币 = `击败数 × 800 + 剩余时间 × 10` |

复用第 3/6/9/10 关 Boss 与 Boss 四阶段代码，只改出场顺序与血量。

#### 3.3.3 无尽词缀

每击败 2 轮 Boss，随机追加 1 条词缀，结算显示本局词缀列表：

| 词缀 | 效果 |
|---|---|
| 狂潮 | 刷怪速度 +20% |
| 铁壁 | 敌人血量 +20%，金币 +15% |
| 荆棘 | 接触伤害 +20% |
| 富矿 | 宝石经验 +30%，敌人移速 +8% |
| 猎杀 | 精英出现频率 +50% |

- 词缀最多 4 条，避免后期不可控。
- 本地榜：`endlessBoard` 保存前 5 条 `{char, diff, time, kills, affixes, at}`。

### 3.4 十层之后：旅行地图关卡（4C · P0）

#### 3.4.1 结构、编号与解锁

10 关通关后开启第二部「旅途回响」，共 4 层 × 4 子关 = 16 关，与 `index.html` 的 16 张旅行地图一一对应。

| 层 | 关卡键 | 旅行地图（`TV_DESTS`） | 信件 | 数量 |
|---|---|---|---|---|
| 11 森林 | 11.1–11.4 | `forest` / `fairy` / `ancient` / `cursed` | A / H / N / P | 4 |
| 12 小镇 | 12.1–12.4 | `town` / `moon` / `nightmare` / `dream` | C / M / Q / R | 4 |
| 13 大海 | 13.1–13.4 | `sea` / `island` / `atlantis` / `merfolk` | B / S / T / U | 4 |
| 14 雪地 | 14.1–14.4 | `snow` / `ruins` / `ice` / `empire` | D / E / F / G | 4 |

- 解锁链：通关 10 → 11.1；每关通关解锁同层下一关；通关 `x.4` 解锁下一层的 `x+1.1`。
- 显示格式统一为 `11.1 森林边缘`，内部仍保留连续序号 `n = 11…26`，不改现有数组索引与 `stageClear` 数值模型。
- `stageBest` 记录键改用 `st.key || n`：`'11.1'`、`'11.1:hard'`；1–10 关未设 `key` 时回退 `'1'…'10'`，旧记录无需迁移。
- `playableCount()` 从 10 变为 26；所有「通关全部」成就必须显式写成 `>=10 / >=14 / >=26`，不能继续用 `playableCount()`。

关卡数据建议：

```js
{ n:11, key:'11.1', layer:11, sub:1, map:'forest',
  name:{zh:'森林边缘',en:'Forest Edge',ja:'森のほとり',ko:'숲의 가장자리'},
  dur:210, bossHp:7200, hpMul:2.80, spdMul:1.36, spawnMul:2.80,
  bg:['#16302a','#0d1d1a','#050b09'], edge:'rgba(120,230,170,.24)',
  hazard:['fog'], letters:['A1','A3','A15'] }
```

`stageDef(n)` 继续按序号取；`stageName(st)` 改为 ``st.key ? st.key + ' ' + 本地化名称 : 本地化名称``（1–10 保持原名）；`bestKey(n,diff)` 改为读 `stageDef(n).key || n`。

## 四、内部优化

### 4.1 设置与反馈落地（4A · P0）

`settings` 三个字段目前完全未接入，Plan 4 第一批就补齐：

- 开始页新增「⚙️ 设置」入口，暂停页也放一个。
- 设置项：
  - 伤害数字开/关（**需要先实现伤害数字**）。

伤害数字实现建议：

```js
G.pops = []; // {x,y,vy,txt,color,life}
function addPop(x, y, txt, color){ if(!svSettings().dmgNum || G.pops.length > 60) return; ... }
```

- 普通伤害白色、暴击金色、治疗绿色、机关伤害红色。
- 上限 60 条，0.6s 上浮淡出，低功耗不生成。

### 4.2 性能（4A/4E · P0/P1）

| 项 | 现状 | 目标 | 做法 |
|---|---|---|---|
| HUD | `updateHUD()` 每帧写 DOM | ≤10 次/秒 | 计时/分数 10Hz；血条/经验条仅在变化时写 |
| 碰撞 | 子弹 × 敌人全量遍历 | 网格粗筛 | 96px 均匀网格，每帧重建敌人桶；只查邻近 9 格 |
| 数组删除 | 可能 `splice` | O(1) | swap-remove + 尾部 pop |
| 对象分配 | 敌人/子弹/粒子每帧新建 | 复用 | 固定容量对象池，`active` 标记 |
| 渐变 | 部分每帧 `createRadialGradient` | 缓存 | 按关卡/颜色缓存，切关清空 |
| 震屏/阴影 | 低功耗已关 | 保持一致 | 统一读 `PERF.shadows / settings.shake` |
| 自适应画质 | 只有手动低功耗 | 自动降级 | 连续 3s <50fps 降一档；稳定 10s >58fps 升一档 |
| 音频并发 | 无限制 | ≤6 个同时 | 计数 + 主增益，超限丢弃低优先级音 |

性能预算（中端手机 / 1280×720 / DPR 2）：

| 指标 | 目标 |
|---|---|
| 普通模式 | 120 敌人 + 60 子弹 + 220 粒子 ≥ 55fps |
| 低功耗 | 稳定 30fps，CPU 占用明显低于普通 |
| 单帧逻辑 | ≤ 8ms |
| 单帧渲染 | ≤ 8ms |
| 10 分钟内存 | 无持续增长，GC 峰值 ≤ 8ms |

### 4.3 存档与稳定性（4A · P0）

- **v3 → v4**：只增字段，`normSv` 继续兜底。
- 写入统一走 `saveSv()` / `writeSave()`，禁止散落的 `localStorage.setItem`。
- 备份：写入前把旧值放 `idle-yueba-save-v3-backup`，解析失败时尝试回滚。
- 配额失败：`QuotaExceededError` 时 toast「存档失败，请清理空间」，并在设置页显示。
- 导出/导入：设置页提供「复制存档 JSON」与「粘贴导入」，便于跨设备迁移。
- 多标签：监听 `storage` 事件，金币变化时提示「另一标签页已更新存档」并重载。
- 错误兜底：`window.onerror` 捕获后 toast，非阻塞；`lastError` 写入存档诊断字段。

### 4.4 工程质量（4E · P1/P2）

| 项 | 内容 |
|---|---|
| i18n 校验 | Node 脚本扫描 `t('key')` / `data-t` 与四语言表，输出缺失键、未使用键；纳入提交前检查 |
| 种子随机 | 抽象 `RNG`，普通模式 `Math.random`，每日/回响用可复现种子 |
| 冒烟入库 | 把现有 DOM 桩冒烟脚本移到 `tests/smoke.js`，一条命令跑完；新增 3D/4B 用例 |
| 调试面板 | 增加 FPS、实体数、单帧耗时、当前种子；仅 `#debugall` 显示 |
| 源码结构 | 4E 可选：拆 `src/data|combat|render|ui|save`，构建时拼回单文件；不改交付形态 |
| 常量集中 | 所有上限/乘区/费用集中到 `BALANCE` 表，避免散落魔法数字 |

### 4.5 输入与可访问性（4A/4C · P1）

- 手柄：Gamepad API，左摇杆移动、A 主动技、Start 暂停；无手柄时零成本。
- 按键重绑：仅 PC，至少支持移动/技能/暂停/重抽。
- 移动端：摇杆可视范围 + 死区 12%；技能按钮放右下，避开系统手势区。
- 安全区：HUD 四角读 `env(safe-area-inset-*)`。
- 色弱：稀有度用形状/角标区分，不只靠颜色。
- 字号：设置里提供 100%/115% 两档 HUD 字号。

## 八、风险与取舍

| 风险 | 应对 |
|---|---|
| 内容铺太多导致数值膨胀 | 新增遗物/武器全部设上限；伤害、冷却、拾取、减伤各有硬上限 |
| 主动技破坏自动战斗节奏 | 只做 4 个角色各 1 个，冷却长、效果偏防御/解围 |
| 每日种子受浮点/帧率影响 | 固定步长模拟 + 种子随机；只保证同设备同版本可复现 |
| 回响 + 难度 + 金币倍率叠加过高 | 金币倍率封顶 ×3；高倍率下不加掉落数量 |
| 单文件继续膨胀到难维护 | 4E 先做校验脚本与常量表；拆源码放最后，不改变交付形态 |
| 16 张地图关卡铺太大 | 拆成 C-1…C-5 五个小批次；每层先用现有敌人/Boss 原型换皮，验证手感后再加签名敌人 |
| 地图主题与主关卡割裂 | 只复用 `TV_DESTS` 的 `specials` 与 `TV_LETTERS`，不新写设定；14.4 与「雪落王庭」共用一套视觉语言 |
| 40 件遗物稀释卡池 | 地图遗物按通关进度逐步解锁；未解锁的地图遗物不进通用抽取池 |

**明确不做**

- 联网排行榜、账号、云存档
- 多人/联机
- 程序化地图与随机房间
- 完整剧情、配音、过场动画
- 广告/内购
- 换引擎或引入构建框架作为硬依赖
