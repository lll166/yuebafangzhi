# i18n 多语言方案（P0 规划件）

游戏：`index.html`（单文件零依赖放置游戏「月巴放置」）
目标：界面文案与全部内容文案支持 **中文 / English / 日本語 / 한국어** 四语言。

> ⚠️ **术语与译法以 [`翻译参考表.md`](./翻译参考表.md) 为唯一权威口径**（含月巴命名法、一人称 `僕`、语体、标点与禁用译名）。本文件第四节是 P0 历史定稿，与参考表冲突时以参考表为准。

## 二、工程口径（P0 已落地）

**两层字典**，避免「用正文当键」的脆弱做法：

| 层 | 表 | 取值函数 | 键 |
|---|---|---|---|
| 界面短文案 | `I18N_UI` | `$t('中文原文')` | 中文原文 |
| 内容条目 | `I18N_BANNY` / `I18N_LETTER` / `I18N_MISC` | `$tn(表, 条目id, 字段, 中文兜底)` | 条目自身 id |

> **函数命名说明**：叫 `$t()` / `$tn()`，**不要**改成 `T()` / `tr()` —— 斗月巴牌型代码里已有大量局部变量 `T`、`tr`（单处 15~20 次引用），会遮蔽全局函数导致译文静默失效。

- **天然回退**：字典缺条目时原样返回中文，因此可以增量补译，任何阶段都不会出现空白或 `undefined`。
- **静态 HTML**：给元素加 `data-i18n`（文本）/ `data-i18n-title`（title 属性），切语言时由 `applyStaticI18n()` 统一刷新。
- **切语言后的重绘**：`applyI18n()` 刷新静态文案 + 顶栏 + 状态栏，并遍历 `_i18nRepaint` 钩子数组重绘当前打开的视图（P1 起逐个挂入 `openBook` / `openTravel` / `openShop` 等）。
- **术语唯一来源**：`I18N_GLOSSARY`（第四节），所有译文一律照它对齐，避免同一概念多种译法。

已落地的代码位置：样式 `.lngrow*`、顶栏按钮 `#btnLang`、i18n 核心块（`I18N_LANGS` 起）、`defaultState()` 的 `lang` 字段、`init()` 中的 `detectLang()` 与 `applyI18n()`。

## 三、翻译顺序（推荐）

原则：**短 → 长，高频 → 低频，界面 → 内容，低风险 → 高文学性**；每个阶段内三语言同时产出，**英译作为语义基准**，再落日、韩。

| 阶段 | 内容 | 规模（盘点值） | 为什么排这里 |
|---|---|---|---|
| **P0** | 框架 + 🌐 开关 + 术语表 + 盘点脚本 | 0 条译文 | 没有统一术语与框架，后面每批都要返工 |
| **P1** | 界面骨架静态文案：顶栏、底部 dock、旅行/斗月巴/飞行三页导航、弹层骨架、通用按钮 | HTML 文本 66 + 属性 14 | 进游戏第一眼就看到；日韩文普遍更长，最早暴露按钮撑破/换行 |
| **P2** | 交互反馈：toast、确认框、错误提示、商店/背包/槽位/番茄钟反馈；**同时完成动态模板参数化**（「🌿 从「X」带回新特产：Y」→ 带占位符的 key） | 短文案 1143 中的主要部分 | 出现频率最高；带变量的模板必须先改成可插值，否则后续内容无法翻译 |
| **P3** | 专名表：月巴名 152 → 地图 16 → 特产 30 → 皮肤 21 → 成就名 40 → 道具/商店物品 | 约 300 | 短、复用广，翻完整体「看起来」已是外语版 |
| **P4** | 图鉴简介 152 + 作者 + 解锁条件描述 | 约 200 | 与 P3 同源，玩家翻图鉴逐条可见 |
| **P5** | 系统说明长文：帮助文档、斗月巴规则、玩法说明、成就描述 | 长文本中的说明类 | 长但低阅读频次，句式统一后可批量过 |
| **P6** | 信件 57 封（正文 + 落款 + 留言），按地图分批：森林15 → 大海15 → 小镇14 → 雪山13 | 57 篇、三千余字 | 文学性最强、最耗时、最需语气统一；也是旅行玩法的情感核心 |
| **P7** | 事件与彩蛋：图鉴随机事件 92、庭院互动、室内事件 48、斗月巴台词、飞行死亡台词 26 + 胜利台词、番茄机彩蛋 | 约 250+ 条 | 数量大但玩家偶遇式看到，单条短，适合流水线批产 |
| **P8** | 收口：缺漏扫描、四语一致性回归、日期/数字格式、长文排版回归 | — | 最后统一验证 |

进度逐项记录在 `tasks.md`。

## 五、盘点结果（P0 产出）

脚本：`specs/i18n/extract-strings.mjs`（用法：项目根目录执行 `node specs/i18n/extract-strings.mjs`）
输出：`specs/i18n/strings.json`（含 `summary` / `phrases` / `items` 三段）

当前 `index.html` 盘点值：

- 唯一文案 **2386** 条（共出现 3080 次）
  - 界面短文案（≤12 字）**1143** 条 → 主要落在 P1/P2
  - 内容长文本（>12 字）**1243** 条 → 主要落在 P3~P7
  - JS 字符串 2306 / HTML 文本 66 / HTML 属性 14
- **可翻译中文片段 2456 个**（共出现 3479 次）——这才是真正的翻译单元；`items` 里的整段 HTML 模板只作上下文参考。

> 结论：全量四语（中→英/日/韩）约为 **2456 × 3 ≈ 7400 条**译句，分批推进是唯一可行的做法。
> 每批完成后重跑一次盘点脚本，`items` 中新出现的中文即未翻译项，可用于 P8 缺漏扫描。

## 六、每批翻译的固定动作

1. 对照 `strings.json` 取本批中文条目；
2. 照 `I18N_GLOSSARY` 对齐术语后填写对应表（`I18N_UI` / `I18N_BANNY` / `I18N_LETTER` / `I18N_MISC`）；
3. 把用到该文案的渲染处改为 `$t(...)` / `$tn(...)`，或给静态元素补 `data-i18n`；
4. 挂入 `_i18nRepaint` 的视图重绘钩子（若该视图是常驻打开态）；
5. 静态解析校验 + 切到三语言各看一遍（长文重点看换行与按钮撑破）。
