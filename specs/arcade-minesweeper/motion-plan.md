# 「扫月巴」动效增强计划书

> 范围：只改 [minesweeper.html](../../minesweeper.html)，不触碰父页 [index.html](../../index.html)；不引入依赖、图片、字体或新文案。
> 目标：把「有结果、没过程」的操作补上即时反馈；保持单文件、可离线、低功耗可关闭。

---

## 一、结论先行

现有动效已经覆盖了「翻开 / 封条 / 踩雷 / 胜利 / 结算 / 菜单入场」的结果瞬间，但真正高频、最能提升手感的几个环节还是**静默**的：

1. 零区扩散是一次性突然铺开，没有「涟漪」传播感；
2. 长按封条 350ms 等待期间没有任何进度反馈；
3. HUD 的剩余小偷、剩余敲一敲、计时数字变化时完全不动；
4. 「敲一敲」只有一声提示音和一次瞬开，缺少仪式感；
5. 胜利时所有雷同时盖上封条，缺少「逐格清扫完毕」的收束感；
6. 结算星级、金币、新纪录都是静态文本；
7. 模式切换（翻 / 封）只换图标，玩家容易误操作；
8. 菜单卡、每日卡、成就解锁缺少「可点 / 不可点 / 刚解锁」的动效语言。

建议按 **P0 手感 → P1 高潮 → P2 氛围** 三批做，全部以 CSS 动画为主、`transform/opacity` 优先，并统一挂到现有的 `fxOff()`（低功耗 / `prefers-reduced-motion`）开关下。

**如果只做 6 个：** 零区涟漪、长按进度环、HUD 数值反馈、敲一敲演出、胜利封场波浪、结算星级逐个弹出。

## 三、可增加动效的位置

### A. 棋盘内操作

| 编号 | 时机 | 建议动效 | 落点 | 成本 | 优先级 |
|---|---|---|---|---|---|
| A1 | 第一次翻开 | 首格「落墨」：格子 1.12 → 0.96 → 1 的弹性压缩，边缘一圈纸纤维小点（≤8 颗，棕色/金色），棋盘四角框线闪一下 | `onCell` 首开分支 L1698-1703；新增 `inkAt(i)` | 低 | P0 |
| A2 | 零区扩散 | 用 BFS **深度**而不是遍历顺序做延迟：第 n 圈延迟 `n*14ms`（上限 220ms），形成由点击点向外扩散的涟漪；同时给 0 格加一层淡色内阴影脉冲 | `revealCell` 改队列 + `depth`；CSS 新增 `waveIn` | 中 | P0 |
| A3 | 数字露出 | 数字单独包一层 `<span class="num">`，出现时 `numPop`（0.7 → 1.12 → 1，带 1px 下压），颜色由浅到实；只动画数字，不动格子背景 | `paintCell`；注意自检假节点 | 低 | P1 |
| A4 | 贴 / 撕封条 | 盖章：从手指按下点作为 `transform-origin`，1.35 → 0.94 → 1 的「砸下」；周围一圈浅色尘点。撕封条：120ms 的翘边淡出 | `toggleSeal` L1391-1401；long-press 记录局部坐标 | 低 | P0 |
| A5 | chord | 已满足数字时描边改为 2s 呼吸；成功连锁时源格闪一下、邻格跟随涟漪；封条数不匹配时格子左右抖 2px + 低音提示 | `updateChordReady` L1415-1421、`chord` L1428-1446 | 低 | P1 |
| A6 | 长按封条 | 按下即出现 350ms 进度环（跟随手指格子），松手/移动取消时环淡出；完成后无缝接 A4 盖章 | `pointerdown/up/move` L1883-1911；用 `::before` 画环 | 中 | P0 |
| A7 | 转屏 / 旋转 | 不做真实旋转动画（内容已重排，强行动画会闪）；只在 `syncOrientation` 后给棋盘 160ms 的透明度回弹，掩盖重绘 | `syncOrientation` L1358-1368 | 低 | P2 |

**A2 的实现要点**

- 把 `revealCell` 的 `stack` 换成 `queue`，记录 `depth[]`；
- 延迟 = `Math.min(depth*14, 220)`，保留现有的 `paintCell(k, delay)` 接口；
- 0 格扩散的每一圈同时出现，比现在的「深度优先随机顺序」更像水波；
- 转屏重绘时统一 `paintCell(i)`（不带 delay），并清空 `el.style.animationDelay`。

**A6 的实现要点**

- 按下时给格子加 `.pressing`，`::before` 用 `conic-gradient` 画环；
- 用 CSS `@property --lp` 从 0 过渡到 1（350ms），不支持 `@property` 的环境退化为一条 350ms 旋转扫描线；
- 移动超过 10px 或 `pointerup` 时移除 `.pressing`，行为与现有长按判定完全一致，不改 `LP_MS`。

### F. 明确不做

- Canvas / WebGL 粒子引擎、全屏彩带、长时间循环光效；
- 每帧 JS 驱动的动画循环（现有 DOM 棋盘不适合）；
- 转屏时的真实 90° 旋转动画（数据已重排，容易闪）；
- 修改核心规则、难度、计时、金币逻辑；
- 新增文案 / 语言键（印章用图标，成就与 toast 沿用现有文本）；
- 音效重做（只在必要处复用现有 `tone()`，如盖章、敲击）。

## 五、技术约定

### 5.1 CSS 优先

- 新增 keyframes 统一放在现有棋盘动画区（CSS L264-302）与结算区（L342-417）附近；
- 只动画 `transform`、`opacity`，必要时用 `filter`；**不**动画 `width/height/top/left/box-shadow`；
- 连续动画只允许出现在「当前 chordready 的几个格子」与「图标呼吸」上，禁止 480 格常驻动画；
- 错峰统一用 `--d` 变量，JS 只写一次 `style.setProperty('--d', ...)`。

### 5.2 JS 小工具（只加必要的）

- `retrigger(el, cls, ms)`：移除类 → 强制回流 → 加类，`animationend` 或定时器移除；所有一次性反馈共用；
- `bumpNumber(el, from, to)`：HUD 翻牌，纯文本 + 两个类，不复制节点；
- `countUp(el, target, ms)`：金币滚动，`fxOff()` 时直接落值；
- `inkAt(i)` / `knockAt(i)`：覆盖层粒子与尘环，沿用 `splashAt` 的坐标换算和 700ms 清理；
- 所有特效函数首行判 `fxOff()` / `G.test` / `G.cells[i]` 是否存在；自检假节点没有 `getBoundingClientRect`，必须提前返回。

### 5.3 与现有状态的兼容

- `paintCell` 的 `animationDelay` 改为「有延迟才写，否则清空」，并在 `rotateBoard` 重绘时清掉临时动画类；
- 新特效类名统一前缀 `fx-`，不与 `open / seal / mine / boom / lost / chordready` 抢占同一属性；
- 同一元素需要多段动画时用 `animation: a, b` 合并，而不是覆盖；
- `startGame` / `backToMenu` 清理所有覆盖层节点与临时类，防止快速重开残留。

### 5.4 性能预算

- 单次粒子 ≤ 16 颗（现有 12 颗）；
- 单次错峰总时长 ≤ 320ms，结算弹层延迟 ≤ 520ms；
- 首次进入对局、零区大扩散、胜利封场三处需实测长任务 < 50ms；
- 低功耗 / 减少动态下：不生成粒子、不扫光、不震动、不做数字滚动，仅保留静态高亮。

## 六、验收

1. `?selftest=1` 仍为 **8/8 PASS**，控制台无异常；
2. 桌面、390×844 竖屏、844×390 横屏三种视口下棋盘尺寸与现状一致，无溢出；
3. 手动走查：普通局首开、零区扩散、长按封条、撕封条、chord 成功 / 失败、敲一敲、踩雷、胜利、每日局、成就解锁、重开、返回、转屏；
4. 转屏前后数字 / 封条 / 立绘 / 翻开数不丢，重绘不误触发首开或盖章动画；
5. `body.lowpower` 与系统「减少动态」下，所有新增动效静默，功能不受影响；
6. 用 rAF 计数在大扫除（30×16）零区扩散与胜利封场时采样，目标 ≥ 50fps，无 > 50ms 长任务；
7. 不新增网络请求，不新增文案键，父页仍保持 `hidden:true`。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 翻格 flip、封条 stamp 与新动画互相覆盖 | 用独立 `fx-` 类 + 多动画合并，不改原类的 `animation` |
| 480 格同时错峰导致长任务 | 延迟上限 320ms、只做 `transform/opacity`、必要时按圈合并 |
| 转屏重绘后旧延迟残留 | `paintCell` 清空 `animationDelay`，重绘前移除 `fx-` 临时类 |
| `@property` 在旧内核不可用，长按环失效 | 检测 `CSS.registerProperty`，降级为旋转扫描线，不阻塞封条逻辑 |
| 敲一敲演出让翻格显得「慢半拍」 | 翻格即时发生，尘环只是不阻塞的覆盖层；低功耗下缩到 200ms |
| 结算延迟过长 | 胜利封场总时长控制在 520ms 内，低功耗恢复即时 |
| 特效节点残留 | 统一 700ms 自动移除；`startGame` / `backToMenu` 兜底清理 |

---

## 八、预期手感

- 点击 → 落墨 / 涟漪：`0-220ms`，反馈明确但不等动画；
- 长按 → 进度环 350ms，松手即盖章，形成「按下去有重量」；
- 敲一敲 → 按钮 → 尘环 → 聚光 → 翻开，约 550ms，是全局最有记忆点的一段；
- 胜利 → 封条逐格落下 → 中央印章 → 星级逐颗弹出，约 900ms 收束；
- 全程不改变现有难度、计时、金币与存档口径。
