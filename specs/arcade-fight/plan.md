# 「月巴拳魂」街机格斗 · 计划书

> 状态：待确认（未开始实现）
> 目标：在「百巴箱」里新增第 3 个独立小游戏 `fight.html`，玩法为 2D 横版街机格斗；每轮从图鉴带外链立绘的月巴中随机抽 10 只组成一组，玩家选 1 只（或番茄）逐关击败对手的月巴。
> 形态对齐：与 `survivor.html` / `snake.html` 相同的「独立单文件 HTML + index 内 iframe 打开」模式，关闭即卸载。

## 二、产品定位

- 一句话：**把「月巴图鉴」变成一台随机轮换阵容的像素街机**——每轮 10 只月巴登台，打完一轮才换下一批。
- 情绪关键词：90 年代街机厅、投币、CRT、像素、番茄汁、打击感、K.O. 定格。
- 随机组的意义：每轮选角都有新鲜感；失败时组不换，可以反复研究同一批对手；通关才算「换台」，把通关变成真正的进度节点。
- 与已有小游戏区分：
  - 幸存者 = 俯视角割草；蛇月巴 = 像素贪吃蛇；斗月巴 = 卡牌对局；**月巴拳魂 = 动作格斗**，补上百巴箱里唯一缺的「手感型」品类。
- 单次体验：一局 30–60 秒，一轮闯关 6–10 分钟，适合碎片时间，也留有刷分空间。

## 三、玩法设计

### 3.1 核心循环

```
标题 → 抽组（随机 10 只月巴，无重复） → 选角（组内任选 1 只 / 番茄）
     → VS 登场 → 三局两胜 → 胜利结算（回血 + 三选一增益）
     → 下一关 …… → 组内终战 Boss → 通关结算 → 换下一组
     ↘ 战败 → 续关（不换组）→ 用尽续关 → 本轮结束（组保留）
```

### 3.2 单局规则

| 项 | 规则 |
|---|---|
| 回合 | 三局两胜，单回合 60 秒 |
| 血量 | 100（角色间 85–125 浮动） |
| 时间到 | 按剩余血量百分比判胜；相同则进入 15 秒绝杀局 |
| 击倒 | 血归零即 K.O.，播放定格 + 慢动作 + 番茄汁飞溅 |
| 续关 | 每轮闯关 2 次续关机会（共 3 条命），失败消耗 1 次并重打当前关 |
| 关间 | 回复 30% 血量，并从 3 个随机增益中选 1 个（可叠加） |
| 计分 | 伤害分 + 连击加成 + 剩余时间 + 无伤/完美奖励；本地 Top 5 记录 |
| 组锁定 | 一组 10 只在**未通关期间永久固定**：退出重进、关闭 iframe、续关、换角色都读取同一组 |
| 换组 | **仅通关时**轮次 +1，旧组写入历史，重新抽 10 只；失败与主动退出都不换组 |
| 组展示 | 选角页显示「第 N 组 · 10 只」；通关结算展示下一组 10 只的剪影预告 |

### 3.3 操作

| 动作 | 键盘 | 触屏 |
|---|---|---|
| 移动 | A / D 或 ← / → | 左半屏虚拟摇杆（左右） |
| 跳跃 | W / ↑ | 摇杆上推 |
| 格挡 | S / ↓（按住） | 摇杆下推（按住）/ 右下「盾」键 |
| 轻击 | J | 右侧「拳」大按钮 |
| 重击 | K | 右侧「重」按钮 |
| 投番茄 | L | 右侧「🍅」按钮 |
| 冲刺 | 双击方向 / Shift | 双击摇杆方向 |
| 超必杀 | 空格（槽满时） | 槽满后「拳」按钮变为「超」 |

- 自动面向对手，不做八方向移动；手感目标：按下即出、零输入延迟、1:1 摇杆跟随。
- 触屏按钮直径 ≥ 56px，底部留 safe-area；竖屏优先，横屏自动放大舞台。

### 3.4 战斗数值（首版基准，集中配置便于调平衡）

| 动作 | 伤害 | 前摇 | 判定 | 后摇 | 击退 | 硬直 |
|---|---|---|---|---|---|---|
| 轻击 | 5 | 5f | 2f | 7f | 30 | 12f |
| 重击 | 11 | 11f | 3f | 16f | 90 | 20f |
| 投番茄 | 8 | 9f | 飞行物 | 12f | 70 | 16f |
| 超必杀 | 24（多段） | 15f | 8f | 24f | 220 | 30f |

- 受击硬直、击退、短暂无敌帧（受击后 0.18s）；格挡减伤 75%，破防硬直 1.2s。
- 番茄槽：最多 3 颗，约 3.2s 回 1 颗；超必杀槽靠命中/受击积累，满槽释放。
- 连击伤害递减：第 1 段 100%、2 段 85%、3 段 70%、4 段 55%，避免无限连。
- 反击（Counter）：对手出招前摇内命中，伤害 +20% 并造成踉跄。
- 打击反馈：轻击 45ms 顿帧、重击 70ms、超必杀 110ms；屏幕震动、冲击环、数字飘字、连击计数。

### 3.5 随机月巴组（核心机制）

**一组 10 只，组内固定，通关才换组。**

| 项 | 规则 |
|---|---|
| 总池 | 图鉴 `TYPES / TYPES2 / TYPES3` 中所有带 `img` 外链立绘的月巴，按 id 去重（约 50+ 只）。实现时把 id / 名称 / 立绘地址 / 稀有度 / 体型固化成 `POOL` 常量，**不依赖主存档** |
| 抽组 | 每次抽 10 只，id 不重复；用可复现的种子随机（seed + 结果 id 列表一起存盘） |
| 组锁定 | 通关前永久固定：退出、重开、刷新 iframe、续关、换角色都使用同一组，绝不重抽 |
| 换组 | **仅通关触发**：轮次 +1 → 记录旧组 → 抽新一组 → 选角页展示「第 N 组」 |
| 选角 | 组内 10 只任选 1 只；**番茄为固定常驻角色**，始终可选、不占 10 只名额 |
| 对手 | 从组内剩余月巴中排 6 名常规对手 + 1 名终战 Boss（按战力升序，Boss 为剩余中最强）；玩家选番茄时组内 10 只全部进入对手池 |
| 观众 | 未登场的 2 只作为背景观众剪影，让整组都有存在感 |
| 组构成约束 | 4 种原型各至少 2 只；体型不做排除，统一把立绘**放大/缩小**到 84 / 96 / 112px 三档，受击框保持一致；池子不足时自动放宽，保证能抽出 10 只 |

**招式按 4 种原型分配**，不为 50+ 只角色各写一套招式：

| 原型 | 定位 | HP | 移速 | 招牌技 | 说明 |
|---|---|---|---|---|---|
| 力量型 | 坦克·压制 | 120 | 155 | 肉弹冲撞（霸体突进） | 高伤、前摇长，适合贴脸 |
| 速度型 | 快攻·游走 | 88 | 225 | 蛇行突进（低姿态） | 低血、连段快，惩罚失误 |
| 均衡型 | 标准·牵制 | 100 | 190 | 回旋拳（短距击退） | 无短板，新手友好 |
| 波动型 | 远程·控场 | 95 | 175 | 番茄炸弹 / 金币散射 | 弹道压制，怕近身 |

- 原型由 **角色 id 哈希**决定，同一只月巴在任何组里都是同一原型，方便玩家记角色；稀有度只影响 Boss 化的加成，不影响公平性。
- 每只角色在原型基准上做 ±8% 的种子化浮动（HP / 移速 / 伤害），保证「同型不同手感」。
- **立绘像素化（HD-2D）**：统一预烘焙成像素精灵，屏高分 84 / 96 / 112 三档（按稀有度与体型分配，只影响观感，不影响判定）；先缩到低分辨率再最近邻放大，得到硬边像素；加暗色底盘 + 暖色轮廓光 + 落地阴影与轻微泛光。**不按立绘宽度算受击框**，超大立绘只放大、不占便宜。
- **不做逐图调色板量化**：外链立绘会污染 canvas，`getImageData` 不可用；改用统一对比度/饱和度预处理 + 角色限定色 + 舞台同色系打光，让不同画风收敛到同一套 HD-2D 舞台质感。
- Boss 化：同一立绘，HP ×1.4、伤害 ×1.15、加金色像素光环与二阶段招式，不换模型。

### 3.6 关间增益（7 选 3）

| 增益 | 效果 |
|---|---|
| 番茄补给 | 番茄上限 +1 或回充速度 -25% |
| 重拳 | 重击伤害 +20% |
| 轻快 | 移速 +12%，冲刺冷却 -20% |
| 铁壁 | 格挡槽 +30，恢复 +50% |
| 生命 | 最大 HP +15，并立即回复 30 |
| 杀气 | 超必杀槽获取 +25% |
| 吸血 | 命中回复 1.5 HP |

### 3.7 对手 AI

- 状态机：接近 / 拉开 / 出招 / 格挡 / 惩罚 / 跳跃 / 发番茄。
- 按关卡递增：反应延迟 0.34s → 0.14s，进攻欲望 0.35 → 0.8，格挡率 0.15 → 0.45。
- **不作弊**：不读玩家输入、不无限连、连段上限 4 段；重击与必杀必须提前亮光预警，给玩家反应窗口。
- 组内终战 Boss 追加阶段机制：血量 40% 以下进入二阶段，招式节奏变化并解锁全屏技。

## 四、视觉与音效

### 4.1 视觉方向：HD-2D 像素舞台

参考 HD-2D 的「**像素角色 + 电影感高清舞台**」：角色是硬边像素，舞台是高分辨率、有景深和光影的空间，不是整屏低分辨率像素。

- 画面分层（后 → 前）：
  1. **远景**：960×540 高清程序化街机厅 / 夜景，玻璃反光、灯牌光晕、薄雾；预烘焙 2 级景深模糊，运行时只做位移。
  2. **中景**：机台、立柱、观众剪影，清晰但低对比。
  3. **角色**：低分辨率像素精灵（84 / 96 / 112px 三档），最近邻放大 2–3 倍，硬边；加暖色轮廓光、接触阴影、轻微泛光。
  4. **前景**：虚化的栏杆 / 番茄箱剪影，随镜头轻微视差，强化景深。
- 光照：三盏舞台聚光灯（暖白主光、番茄红补光、青灰背光）；必杀时压暗舞台、只留角色轮廓光；受击闪白 + 像素火花。
- 像素规范：
  - 角色与 UI 使用 **13 色限定调色板 + Bayer 4×4 抖动**；舞台允许同色系 3–4 级明暗与加色光，不引入高饱和霓虹。
  - 画布整体 960×540、平滑缩放；**只有角色精灵**用低分辨率 + 最近邻，保证「人像素、景不像素」。
  - 血条、计时器、分数用**自绘 5×7 点阵数字**；菜单文字用等宽粗体 + 硬投影，不引入外部字体。
  - 扫描线作为可选的 CRT 滤镜（默认 15% 轻量），默认不做桶形畸变；低功耗自动关闭。
- 角色 / UI 调色板（13 色）：

  | 色 | 值 | 用途 |
  |---|---|---|
  | 墨黑 | `#0b0709` | 底、描边 |
  | 深褐 | `#1a1013` | 舞台暗部 |
  | 暗红 | `#3d1d18` | 背景砖墙 |
  | 砖红 | `#7a2a1f` | 中景 |
  | 番茄红 | `#c23a25` | 主色、血条 |
  | 亮番茄 | `#ed5b35` | 受击、特效 |
  | 奶油 | `#f6c98f` | 次级文字 |
  | 高光 | `#fff0cf` | 主文字、闪白 |
  | 黄铜 | `#8a6a3b` | 机台边框 |
  | 金 | `#d9a441` | Boss 光环、通关 |
  | 暖灰 | `#5a5a52` | 阴影、观众 |
  | 冷灰 | `#2f3b34` | 远景楼房 |
  | 青灰 | `#7fb0a0` | 极小面积点缀（灯牌） |

- 背景实现：远景 / 中景 / 前景各缓存为一张离屏图，运行时只做慢速视差和镜头缩放；尘埃、光斑为对象池粒子，不做逐帧 filter。
- HUD：分段式像素血条（20 格）、左右角色名、回合点、中央倒计时；左下超必杀槽，右上连击数。
- 演出：VS 像素立绘叠在绘景舞台上对撞、受击闪白与硬边冲击星、K.O. 大字印章 + 泛光、终局慢动作（0.25×，0.6s）、舞台灯随胜负切换。
- 立绘统一像素化（见 3.5）：84 / 96 / 112px 三档预烘焙 + 暗底 + 暖色轮廓光 + 落地阴影 + 轻微泛光；战斗动作连续插值，UI 与背景演出用 `steps()` 硬跳，保留复古节奏。

### 4.2 音效

- Web Audio API 实时合成，不引入音频文件：出拳闷响、重击低频、格挡金属声、番茄爆汁、KO 铜锣、观众欢呼噪声、菜单咔哒。
- 音色统一为 **8-bit 芯片音**：方波主旋律 + 三角波低音 + 噪声打击；BGM 为 8 小节循环，可单独关闭。
- 低功耗模式默认关 BGM、减少粒子与扫描线。

## 五、数据与主游戏的关系

### 5.1 存档结构（独立）

```js
// localStorage: yueba-fight-v1
{
  v: 1,
  cycle: 3,                         // 当前第几组（通关才 +1）
  group: {
    seed: 1735021,
    ids: ['mb_pang', /* ... 共 10 只，不重复 */],
    createdAt: 0,
    cleared: false
  },
  groupHistory: [ { cycle:2, ids:[/*10*/], clearedAt:0, score:0 } ],   // 只留最近 20 组
  records: { games:0, wins:0, losses:0, clears:0, bestStreak:0, bestScore:0, top5:[] },
  fighterWins: { tomato:0, mb_pang:0 },
  usedFighters: { mb_pang:1 },      // 用于「十巴十色」类成就
  ach: { first_win:1, /* ... */ },
  settings: { muted:false, lowPower:false, bgm:true },
  lastRun: { stage:0, continues:2, buffs:[] }
}
```

- 组一旦写入存档就固定；**读取时校验 ids 长度为 10 且无重复**，损坏则重抽。
- 通关流程：`group.cleared=true` → 写入 `groupHistory` → `cycle+1` → 抽出新组。任一环节中断，下次进入仍可继续。
- 存档体积 < 10KB，不含图片。

### 5.2 与主游戏

- **完全独立**：不读、不写主存档 `idle-yueba-save-v2`，不改主游戏成就，避免与首页 5 秒自动存档互相覆盖（蛇月巴同款策略）。
- 角色总池直接固化在 `fight.html` 的 `POOL` 常量里，所以「随机 10 只」不依赖玩家收集进度，任何玩家打开都有完整池子。
- 若后续要做经济回传，再增加 `postMessage({type:'yueba-gb-reward'})` 与父页面幂等发奖（见待确认）。

## 六、技术方案

| 模块 | 方案 |
|---|---|
| 渲染 | Canvas 2D，舞台 **960×540**；整体平滑缩放，角色精灵用 84/96/112px 低分辨率源 + 最近邻绘制；DPR = min(devicePixelRatio, 2) |
| 游戏循环 | 固定 60Hz 累加器更新 + rAF 渲染；`visibilitychange` / iframe 卸载即暂停并释放 |
| 图像 | 只预加载**当前组 10 只 + 番茄**；外链立绘先缩到目标屏高、禁用平滑，再缓存为像素精灵；失败回退程序化月巴（图鉴 color + shape） |
| 像素处理 | 不调用 `getImageData`（外链图会污染 canvas）；角色走低分辨率 + 最近邻，舞台走高清渐变/光照；泛光与景深全部预烘焙贴图 |
| 抽组 | 种子化 PRNG（mulberry32 之类），抽 10 只去重，按原型约束重抽；seed 与 ids 一起存盘，保证可复现 |
| 碰撞 | 统一 AABB 受击框/推箱，与立绘尺寸解耦；`#debug` 显示帧数、判定框、AI 状态、当前组 seed |
| 输入 | 键盘 + Pointer Events 统一虚拟摇杆/按钮；`touch-action:none`，防止 iframe 内滚动与缩放 |
| 特效 | 对象池：像素粒子 ≤120、飘字 ≤20、冲击环 ≤8；远景/中景/前景、泛光贴图、扫描线各缓存一张 |
| 音频 | WebAudio 合成；首次用户手势后解锁；静音/低功耗跟随设置 |
| i18n | `?lang=zh|en|ja|ko`（父页面传入），缺省 zh；所有文案集中字典，同 snake.html |
| 存档 | try/catch 包裹 localStorage，损坏自动重建；抽组、通关、关键成就即时落盘 |
| 低功耗 | 关 BGM、粒子减半、关闭泛光/尘埃/视差/扫描线、DPR 降为 1；像素角色与判定不受影响；`prefers-reduced-motion` 时默认开启 |

### 6.1 文件结构（单文件内分区）

```
fight.html
├─ <style>  街机 HUD / 选角 / 结算 / 触屏控件
├─ <canvas id="cv">
├─ <div>    菜单与按钮（DOM 只做 UI，舞台全 canvas）
└─ <script>
   ├─ I18N / POOL（50+ 月巴池）/ GroupGen（抽组与原型分配）/ SAVE
   ├─ Input / Fighter / AI / Combat
   ├─ Pixel（调色板/抖动/点阵字）/ FX / Audio / UI
   └─ Game（状态机：title → group → select → vs → fight → result → buff → clear）
```

## 八、验收标准

1. 百巴箱卡片出现，图标为番茄月巴立绘；点击内嵌打开，关闭后回到百巴箱，首页番茄钟不断。
2. **同一组 10 只在未通关期间完全固定**：关闭 iframe、刷新、续关、换角色、重进游戏后都是同一批，且无重复。
3. **只有通关才换组**：失败不换；通关后 `cycle` +1 并抽出新的 10 只，旧组可在组历史里查到。
4. 桌面键盘与手机触屏均可完成：移动、跳、格挡、轻击、重击、番茄、冲刺、超必杀。
5. 完整跑通：抽组 → 选角 → 7 关 → 通关/战败 → 续关 → 结算 → 记录落盘 → 再开一局数据正确。
6. HD-2D 观感成立：角色像素硬边清晰、84/96/112px 三档大小可辨，舞台有明确远/中/近分层与景深；HUD 为点阵字体。
7. 中/英/日/韩 四语言 UI 无漏翻、无溢出；竖屏 360×640 与横屏均可用。
8. 无控制台报错；连续游玩 10 分钟无内存增长；切后台自动暂停。
9. 立绘断网/加载失败时自动回退，不影响开局。
10. 主存档不被写入；删除 `yueba-fight-v1` 后可干净重置。

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| 投稿立绘比例/留白差异大，判定不公平 | 统一屏高缩放 + 固定受击框 + 每角色 `artScale/artY` 标定 + `#debug` 判定框 |
| 随机组可能全是远程，节奏单一 | 抽组约束（4 原型各 ≥2）；不满足就重抽，最多 10 次后放宽 |
| 大小差异靠缩放后，视觉压迫感与判定不一致 | 立绘 84/96/112px 三档，受击框统一；大体型只放大观感，不加判定 |
| 像素化后立绘糊成色块、认不出角色 | 84/96/112px 三档 + 暗底 + 轮廓光 + 名字条；`#debug` 提供原图对比 |
| 50+ 角色无法逐个做招式 | 只做 4 种原型 + 共享招式；角色差异靠数值、体型、弹道和 AI 表达 |
| HD-2D 的景深/泛光/聚光灯在手机上耗性能 | 全部预烘焙贴图、对象池化；低功耗一键关闭泛光/尘埃/视差，角色像素与判定不变 |
| 组锁定/换组状态出错（重复、丢组） | 存 seed + ids + cycle；读取校验长度/去重；通关流程分步落盘 + `#debug` 重抽按钮 |
| 外链图失效或离线 | 预加载失败回退程序化月巴；不阻塞开局 |
| 格斗深度不足、很快玩腻 | 街机闯关 + 随机增益 + 刷分 + 角色差异 + 成就；后续再加自由对战 |
| 手机按钮拥挤、误触 | 左摇杆 + 右 3 键，盾并入摇杆下推；按钮 ≥56px；真机校对 |
| 与「斗月巴」定位混淆 | 卡片名与副标题明确「街机格斗」，图标用番茄拳套意向 |
| 单文件过大 | 立绘全部外链、无音频文件；代码按模块分区，目标 ≤ 120KB |
| 平衡性反复 | 数值集中表配置，内置 `#debug` 直选关卡/无敌，快速对局验证 |
